## Rules

- One project per session. Link across projects, never copy.
- **Query session memory before fixing an unfamiliar failure, and after two failed
  attempts at the same operation.** The session corpus is indexed across all
  registered agent stores
  (`scripts/memory/CONTEXT.md` — triggers, survey then `get <chunk_id>`), kept fresh by
  `python.exe scripts/memory_index.py ingest` — never WSL `python3`, which sees no store.
  R14 fails the commit when the index lags or cannot compare; the trigger is a convention nothing invokes.
- Load L0 (this file) always; load one project's L1/L2 on demand.
- Read the target's `CLAUDE.md`, then its `CONTEXT.md`. Load 1 contract + inputs only (~2–8K tokens).
- Per-project maps: `MAP.md` (generated by `scripts/build_project_map.py`, never hand-edit).
- Standalone preflight: every project ships a `preflight.py` (stdlib only). A session
  that starts inside a project runs it first; exit 1 lists exactly what is missing.
  `WORKSPACE_ROOT` env overrides where the siblings live (default: `projects/research/`).
- Experience is local (D11): `## Open work` + `docs/adr/` + optional `EXPERIENCE.md`. Root links, never copies.
- Scars: patrz `SCARS.md`. Read it before editing anything in `scripts/**`, `hooks/**`, `skills/**`, `check_workspace_integrity.py`, `audit_*.py`.
- Archive is two-stage (D10): `grade: demoted` in place → `projects/_archive/` (ungated).
- Answer shape: action first, numbered steps, one next step (`skills/i-have-adhd/SKILL.md`).
- **Closing ritual (default workflow):** any session that changed state ends by
  writing its own flag file `handoff/flags/<flag>.md` (entry shape: `flag` —
  YYYY-MM-DD: state + next step; frontmatter `flag`/`since`/`owner`/`agent`/
  `model`), retiring flags whose claims stopped holding, and rebuilding the two
  generated views — `python scripts/build_handoff.py` (`HANDOFF.md`, one flag =
  one file = one writer; contract `handoff/CONTEXT.md`) then
  `python scripts/build_state.py` (`STATE.md`). Never hand-edit either view
  (ICM inv. 9); `--check` on `build_handoff.py` is the staleness gate. Detail
  stays in the project's own handoff, the root links, never copies (D11/D12).
- Before every `git commit`, run `git diff --check`; any output is a hard stop
  until the whitespace issue is fixed. This is the workspace's only whitespace
  authority, including spaces before CRLF.
- **Never change a gate to let a commit pass.** If a gate fails, fix the data it
  flagged. An exemption (e.g. `agent_commit.py`'s whitespace scope) is its own
  commit with the rationale in the message — never inside a "finish everything"
  commit, and never as silent scope widening. Same rule as `ALLOWED_ROOT`.
- Gate before done: `python scripts/check_workspace_integrity.py`.

## Token efficiency (D13, D15)

- **Integrate `skills/token-hygiene/SKILL.md` on every session start.** It enforces:
  - Anti-SubRetrv: check context before re-reading
  - Anti-ReTest: gate test runs on a source change
  - Persist helpers as scripts, not one-off snippets
  - Scope elision: no blind whole-file reads
  - Delta edits, not rewrites
  - Batch independent calls via `Promise.allSettled`
  - Bash output caps

Evidence: `TOKEN-EFFICIENCY.md`. Re-measure after changes: `python3 scripts/pi_cache_forensics.py --since 7d`.

Context is re-paid every turn. Measured: 78.0% cache hit, 69.5M tokens/29 sessions.
Evidence + scripts: `TOKEN-EFFICIENCY.md`, `scripts/pi_cache_forensics.py`.

- **One model per session, never switch mid-session.** Switching invalidated the KV
  prefix 23× (502K full-price tokens). Roles are thinking modes, not routing targets —
  no architect/editor model split. Model availability is not stable, so if the model
  dies, end the session and restart on another one.
- **Set thinking level before turn 1, then never touch it.** 25 cold prefixes, 812K tokens.
- **Check a model's cache ratio before a long session.** `cacheRead: 0` means the full
  prefix is re-billed every turn: `oc/*` cost 4.0M tokens at a 0.0% hit ratio. Free ≠ cheap.
- **Read once, edit deltas, batch calls.** Re-read ratio 1.17× (target 1.0). Use `edit`
  not `write` on existing files — O(Δ) not O(N). Batch independent calls: fewer turns,
  fewer re-paid prefixes.
- **Cap tool output.** Tool results are 11.7× assistant output and dominate context.
  Pipe through `head`/`tail`/counters. Read symbols, not whole files.
- **Persist helpers as scripts** instead of regenerating near-duplicate test code; gate
  test runs on an actual source change.
- Re-measure after changes: `python3 scripts/pi_cache_forensics.py --since 7d`.
Probes, all stdlib: `pi_token_audit.py` (spend split), `pi_cache_forensics.py`
(why the cache broke), `pi_context_growth.py` (per-turn growth),
`tool_output_breakdown.py` (what tool output is addressable),
`mcp_schema_cost.py` (MCP tool-surface prefix cost), `mcp_call.py` (call one
MCP tool, print payload size).

## Enforcement rules

- **`write`**: new files only. Re-writing an existing file costs O(N) tokens on
  every pass; the edit tool costs O(Δ).
- **`edit`**: all modifications to existing files, including multi-spot changes
  (use multiple `edits[]` entries in one call, not sequential single-spot
  edits).
- **`edit`'s `oldText` must match uniquely.** If it does not match, stop and
  re-read the target region before retrying — do not widen the match
  heuristically.

## jCodeMunch (symbol-level retrieval, measured)

Indexed codebases are queried by symbol, not by reading whole files. Wired into
`~/.pi/agent/mcp.json` as `jcodemunch` with `exposure: codemode` — the 91 tools
never enter the system prefix; only `menu`, `route`, `set_tool_tier` are declared.
Evidence and caveats: `TOKEN-EFFICIENCY.md`.

- **Do not `read` a source file to find or edit code in it.** `menu` → find the
  action → `search_symbols` → `get_symbol_source`. Measured on `audit_map_state`:
  1,300 chars (372 tok) vs 7,669 chars for the whole file, 5.9×. Installing the
  server does not change this habit — the rule does.
- **Structural queries answer what grep cannot**: `find_importers`,
  `get_blast_radius`, `get_call_hierarchy`, `find_dead_code`. Preflight risky
  changes with `check_edit_safe` / `check_delete_safe`; a `terminal: true`
  verdict is final, so do not re-query it.
- **Re-index after editing source** (`index_file` / `index_folder`) or symbols go
  stale; the result carries `_freshness`.
- **This does not touch `bash`.** 75.8% of tool output is shell/test/git output
  and is unaffected. Cap that with `head`/`tail`/counters instead.
- Symbol ids look like `path/to/file.py::name#kind`; `search_symbols` returns
  them. The CLI needs absolute paths — relative ones are rejected.
