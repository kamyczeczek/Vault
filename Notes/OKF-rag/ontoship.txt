# OntoShip

> **A project knowledge base is just `markdown` + a `README` index + `git`.** Nothing simpler works better.

![Zooming into a real knowledge base: repo, folder, document, three entities](docs/img/microscope.gif)

▶ [Watch the full 60-second video](docs/media/ontoship-microscope.mp4): from the whole
knowledge base down to a single line of text and back.

![OntoShip graph of a real project](docs/img/graph.png)

*Above: the actual documentation graph of a live production project
([hub.neuraldeep.ru](https://hub.neuraldeep.ru/)) — generated by `gitmark map`, gravity
mode on. Colors = services. This isn't a mockup; it's a KB being used and evolved daily.*

On that project today: **421** markdown docs, **568** links between them, **88** `README`
indexes, **617** commits to the KB since March 2026. `gitmark index` rebuilds the whole
thing in **1.5 s** with ~50 MB of RAM.

---

## The idea

Markdown is the source of truth — the thing you and your AI assistant read directly, in
any editor. Everything **derived** (a search index, this HTML overview, the link graph) is
**regenerated** from the md, so git stays clean. No service, no database, no embeddings,
no vendor. The entry point is `CLAUDE.md` / `AGENTS.md`; every folder's `README.md` is its
index.

```
CLAUDE.md / AGENTS.md      ← entry point
/docs
  README.md                ← master index
  /services
    /<service>
      README.md            ← always the folder index
```

Battle-tested over months of building with AI assistants. The KB an agent (and a human)
actually wants is plain md you can read anywhere — *plus* instant search so you find the
right file instead of grepping blind.

## Under the microscope

Zoom in on the knowledge base and every level is still something you can open in a text
editor:

| zoom | level | what it is |
|---|---|---|
| ×1 | the whole KB | a graph of md files linked to each other; agents and humans read the same thing |
| ×10 | a folder | a `README.md` index plus the docs it points to |
| ×100 | a document | plain markdown: a small frontmatter header, headings, links |
| ×1 000 | the header | three entities: object, properties, links (see the ontology below) |
| ×10 000 | the atom | one line of text, e.g. `node_type: runbook`. git diffs it, `gitmark`/`grep` find it, an agent reads it |

![Four zoom levels: folder, document, three entities, a line of text](docs/img/microscope-levels.png)

No layer underneath needs a database, a schema or embeddings.

## What's in here

**`gitmark`** — one self-contained Python-stdlib CLI, zero dependencies:

| command | what |
|---|---|
| `index` | build a SQLite **FTS5** index of sections + frontmatter (title, description, tags, type, status, trust) and typed links |
| `search` | ranked per file: section bm25 + title/description bm25 + trigram substring + fuzzy (typos, Russian morphology), fused with RRF; `--type/--status/--service` filters; `--json` |
| `query` | structured questions over frontmatter, straight from md: `query type=decision status!=deprecated`, `query type=plan --count-by service`, `query trust=unverified 'generated.by~claude'` |
| `map` | self-contained **HTML**: collapsible tree + rendered markdown + a force/radial **graph** of links |
| `serve` | tiny local HTTP server to view the map |
| `stat` | index/KB stats |
| `lint` | *(optional)* ontology checks I1–I8: frontmatter, vocabularies, orphans, broken links, typed links to missing code, past `stale_after` |
| `health` | KB scorecard: typed %, description %, typed links, orphans, trust tiers, stale, duplicate docs |
| `version` | — |

OntoShip ships the **`gitmark`** plugin (KB + dev-flow) as a Claude Code marketplace.
(The **`destructive-guard`** safety hook now lives in its own repo →
[vakovalskii/destructive-guard](https://github.com/vakovalskii/destructive-guard).)

**`gitmark`** — three skills and five commands:

| skill | what |
|---|---|
| `kb-search` | search the KB (FTS5) instead of grepping blind |
| `kb-curate` | light ontology rules when adding/editing docs (types, frontmatter, typed links) |
| `dev-flow` | the spec-driven loop to ship a feature: research → tasks → goal → **spec (md via `kb-curate`)** → isolated **git worktree** → implement → tests → independent review → dev-tests → prod-tests → ship (MR → `dev` → `main`). Feature to prod in ~40 min – 2 h. |

So the agent searches the KB instead of grepping, follows light curation rules when
editing, and ships changes through one repeatable, gated flow built around the KB.

| command | what |
|---|---|
| `/kb` | search the KB (FTS5) and answer from the top hits |
| `/kb-map` | build the self-contained HTML graph of the KB and open it |
| `/doc` | compose/update **one** KB doc following the ontology (wraps `kb-curate`) |
| `/onto-doc` | build the **whole** KB — fans out kb-curate curator agents per area, then lint + index + map |
| `/ship` | run the dev-flow on a feature/fix: research → … → ship (MR → dev → main) |

### What to write after a command (for best results)

The argument after the command is the prompt — be specific, results scale with it.

**`/kb <query>`** — a topic, symbol, concept or question to find in the KB.
- Good: `/kb how is the billing webhook signature verified`, `/kb tier rate limits`, `/kb sandbox isolation`.
- Use concrete nouns, not full sentences. Cyrillic, typos and substrings are fine (trigram/fuzzy).
- Bare `/kb` → prints index stats + the syntax.

**`/kb-map [output-path]`** — usually nothing (defaults to `docs-map.html`).
- Optional path: `/kb-map build/graph.html`.

**`/doc <topic / what to document>`** — name the thing to write up; the agent picks the
node_type+folder, writes frontmatter + typed links, and indexes it.
- Good: `/doc how the billing webhook verifies the YooKassa signature`, `/doc decision: drop Firecracker-per-session`.
- It searches first and **edits** an existing doc instead of duplicating.

**`/onto-doc [scope]`** — bootstrap/rebuild the **entire** KB. Empty = whole repo; or scope it
(`/onto-doc services/api services/billing`, or `/onto-doc only reference docs`).
- Surveys the codebase, splits it into doc areas, and **dispatches a curator agent per area**
  (parallel), then lints + reindexes + regenerates the graph.
- Use it on a fresh repo to stand up docs/ from nothing, or to backfill coverage.

**`/ship <what + why + done>`** — describe the change as fully as you can; this is what makes
the dev-flow good. Include **what** to do, **why** (the goal), and the **done-criteria**, and
name the target service/file if you know it.
- Good: `/ship add a 60 rpm rate-limit to /api/search; goal: stop abuse; done = HTTP 429 over the limit + a unit test + a note in docs/reference/limits.md`.
- Weak: `/ship fix search` → the agent has to guess the goal and the done-criteria.
- Add "deploy it" / "don't deploy" if you want to control the last step.

> **Looking for `destructive-guard`?** The `PreToolUse` safety hook that intercepts
> destructive commands (`rm -rf`, `git reset --hard`, `terraform destroy`, `DROP TABLE`…)
> and turns them into a y/n confirmation has moved to its own repo:
> **[github.com/vakovalskii/destructive-guard](https://github.com/vakovalskii/destructive-guard)**
> · [landing + rules reference](https://vakovalskii.github.io/destructive-guard/).

## Quickstart

```bash
python3 skills/kb-search/gitmark.py index            # build .gitmark/index.db
python3 skills/kb-search/gitmark.py search "auth flow"
python3 skills/kb-search/gitmark.py map -o docs-map.html && open docs-map.html
```

Pure `python3` (≥3.7) with SQLite **FTS5**; the **trigram** tokenizer (SQLite ≥ 3.34) adds
fuzzy/substring/non-Latin matching — detected automatically, degrades gracefully. Add
`.gitmark/` to `.gitignore` — it's a build artifact.

## Install as a Claude Code plugin

```text
/plugin marketplace add vakovalskii/ontoship
/plugin install gitmark@ontoship
```

Or just copy `skills/` and `commands/` into your repo's `.claude/` — project-local, no
marketplace needed.

## Optional: the ontology (only if you want guardrails)

The simple core needs **no frontmatter at all** — `index`/`search`/`map` work on raw
markdown. If a team wants the KB not to rot as it grows, there's a light **code-ontology**
(inspired by [Palantir's Ontology](https://www.palantir.com/docs/foundry/ontology/overview)):
each doc gets a `node_type`, a few frontmatter properties, and typed links — and
`gitmark lint` enforces it (no broken links, no orphans, every folder has a README index).
See [`docs/ontology.md`](docs/ontology.md). Use it or ignore it; the tool doesn't force it.

The frontmatter is compatible with Google's [Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md):
`type` works as `node_type`, and `description`, `generated`/`verified` (trust tier) and
`stale_after` are understood by search, `query` and `lint`. On a 198-question benchmark
over seven real project KBs, gitmark 0.2 puts the right doc first 69% of the time
(grep: 30%, 0.1: 47%); adding a one-line `description` to docs lifts it further —
see [docs/decisions/okf-alignment.md](docs/decisions/okf-alignment.md) and [`bench/`](bench/README.md).

Palantir models an organization as objects, their properties and the links between them.
OntoShip borrows exactly those three entities and applies them to knowledge about code:

| Palantir Ontology | in OntoShip | example |
|---|---|---|
| **Object** (object type) | `node_type`: every `.md` is one object of one type | `runbook`, `service`, `gotcha`, `plan`, `decision`, `reference` |
| **Properties** | YAML frontmatter, the object's columns | `title`, `service`, `status`, `updated`, `tags` |
| **Links** (link types) | typed links under `links:`, including links into code | `documents`, `depends_on`, `supersedes`, `part_of` |

The `kb-curate` skill holds the rules for writing them; `gitmark lint` checks the invariants
(every doc has a type, values come from the vocabulary, no orphans, no broken links, every
folder has a README, a superseded doc is marked deprecated).

![Three entities in one real frontmatter header](docs/img/ontology-3-entities.png)

## Why this and not a wiki / Notion / vector-DB memory

Because the simplest thing wins: md you already read, git you already use, one stdlib file
you can audit in an afternoon. It runs offline, leaks nothing to a SaaS, and you own every
byte. There are a thousand "memory banks" — this one's bet is **radical simplicity that you
can watch working on a real product**, not another service to run.

# OntoShip — entry point

OntoShip is a Claude Code marketplace (`ontoship`) shipping **gitmark** — an md+git
knowledge base (FTS5 search, HTML graph, ontology linter) plus the spec-driven dev-flow
built on top of it.

> **destructive-guard** (the PreToolUse safety hook) now lives in its own repo:
> [github.com/vakovalskii/destructive-guard](https://github.com/vakovalskii/destructive-guard).

## Where things live

```
.claude-plugin/        marketplace.json + plugin.json (the gitmark plugin manifest)
commands/              slash commands: /kb /kb-map /doc /onto-doc /ship
skills/
  kb-search/           the gitmark CLI engine (gitmark.py) + SKILL.md
  kb-curate/           rules for maintaining the KB as a typed ontology
  dev-flow/            the gated ship pipeline
docs/                  the knowledge base itself (this is the KB)
```

## Start here

- **Knowledge base** → [docs/README.md](docs/README.md) — master index
- **The model** → [docs/ontology.md](docs/ontology.md) — how docs are typed & linked
- **How it fits together** → [docs/reference/architecture.md](docs/reference/architecture.md)
- **Commands** → [docs/reference/commands.md](docs/reference/commands.md)

## Principle

Markdown + git is the source of truth. Everything derived — the search index
(`.gitmark/index.db`), the HTML graph — is regenerated, never committed as truth.
Every folder's `README.md` is its index; never let a doc become an orphan.

## Maintain

```bash
python3 skills/kb-search/gitmark.py index    # rebuild the index after editing docs
python3 skills/kb-search/gitmark.py lint     # check the ontology (broken links, orphans, frontmatter)
python3 skills/kb-search/gitmark.py map -o docs-map.html   # regenerate the graph
```

# kbbench — retrieval benchmark for markdown KBs

Answers one question with numbers: **given a question, does the engine put the doc that
answers it at the top?** Used to compare gitmark versions against each other and against
`grep` (what an agent does without the skill).

## QA set

JSONL, one question per line, `gold` = repo-relative path(s) of the answering doc:

```json
{"id": "acme-01", "kind": "paraphrase", "q": "how do we roll back a bad deploy?", "gold": ["docs/ops/deploy.md"]}
```

`kind`: `paraphrase` (natural question, not copying the title), `keyword` (2–4 terms you
would type), `typo` (keywords with realistic typos / wrong morphology). Generate ~30 per
repo — an agent reading 30 docs and writing one question each works well; ask it to
describe the need the way someone who has *not* read the doc would.

QA sets describe private projects, so keep them out of git: `bench/local/` and
`bench/results/` are gitignored.

## Run

```bash
python3 bench/kbbench.py \
  --repo acme=~/src/acme --qa acme=bench/local/acme.jsonl \
  --repo beta=~/src/beta --qa beta=bench/local/beta.jsonl \
  --engine grep \
  --engine old=bench/local/variants/gitmark_v01.py \
  --engine new=skills/kb-search/gitmark.py \
  --json bench/results/run.json
```

`--engine NAME=path/to/gitmark.py[,extra,search,args]` — any gitmark-compatible CLI
(`--root R index`, `--root R search Q -k K --json`). The previous version is one
`git show <ref>:skills/kb-search/gitmark.py > …` away.

Engines rebuild `.gitmark/index.db` inside each repo. To leave real repos untouched, run
against a mirror: copy just the `*.md` (+ `.gitignore`, `.gitmarkignore`) into a scratch
dir, `git init` it and `git add` the files the original repo tracks.

Output: hit@1, hit@5, MRR@k overall, per query kind and per repo; search latency; index
time and file count per repo. `--json` keeps per-question ranks and top-5 for failure
analysis.

## Tuning

`gitmark.py` reads `GITMARK_TUNE='{"CHANNEL_W": {...}, "PRIOR": {...}, "RRF_K": 5}'` so
ranking weights can be grid-searched without editing code. Split questions into dev/test
(e.g. odd/even), pick on dev, report test.

## Results so far

See [docs/decisions/okf-alignment.md](../docs/decisions/okf-alignment.md).

#!/usr/bin/env python3
"""kbbench — retrieval benchmark for markdown knowledge bases.

Compares search engines on one or more KB repos against a gold QA set:
"which doc answers this question?" Each engine is a gitmark-compatible CLI
(`--root R index`, `--root R search Q -k K --json` → [{path, ...}]) or the
built-in `grep` baseline (what an agent does without a KB tool: rank files by
how many query terms they contain).

QA set = JSONL, one question per line:
    {"id": "x-01", "kind": "paraphrase|keyword|typo", "q": "...", "gold": ["docs/a.md"]}

Usage:
    kbbench.py --repo NAME=PATH --qa NAME=qa.jsonl [--repo ... --qa ...]
               --engine grep --engine v01=path/to/gitmark.py --engine new=skills/kb-search/gitmark.py
               [-k 10] [--json out.json]

Metrics per engine: hit@1, hit@5, MRR@k (by kind and overall), mean search
latency, index time, number of files the engine indexed.
"""
from __future__ import annotations

import argparse
import json
import os
import re
import subprocess
import sys
import time
from collections import defaultdict
from pathlib import Path

WORD = re.compile(r"[\w\-]{3,}", re.UNICODE)
SKIP_DIRS = {".git", "node_modules", ".gitmark", ".venv", "venv", "dist", "build", "__pycache__"}


# ─────────────────────────── engines ───────────────────────────
class GrepEngine:
    """Baseline: an agent grepping the repo. Score = distinct query terms present
    in the file (case-insensitive), tie-break by total occurrences."""

    name = "grep"

    def index(self, root: Path) -> dict:
        t = time.perf_counter()
        self.docs = {}
        for p in sorted(root.rglob("*.md")):
            rel = p.relative_to(root)
            if any(part in SKIP_DIRS for part in rel.parts):
                continue
            try:
                self.docs[rel.as_posix()] = p.read_text("utf-8", errors="replace").lower()
            except OSError:
                pass
        return {"files": len(self.docs), "index_s": time.perf_counter() - t}

    def search(self, root: Path, q: str, k: int) -> list:
        terms = {w.lower() for w in WORD.findall(q)}
        scored = []
        for rel, text in self.docs.items():
            hits = [text.count(t) for t in terms]
            distinct = sum(1 for h in hits if h)
            if distinct:
                scored.append((distinct, sum(hits), rel))
        scored.sort(key=lambda x: (-x[0], -x[1], x[2]))
        return [r for _, _, r in scored[:k]]


class CliEngine:
    """Any gitmark-compatible CLI."""

    def __init__(self, name: str, script: Path, extra: list | None = None, env: dict | None = None):
        self.name, self.script, self.extra, self.env = name, script, extra or [], env

    def _run(self, root: Path, *args) -> str:
        r = subprocess.run([sys.executable, str(self.script), "--root", str(root), *args],
                           capture_output=True, text=True, timeout=600,
                           env={**os.environ, **self.env} if self.env else None)
        if r.returncode != 0:
            raise RuntimeError(f"{self.name}: {' '.join(args)} → {r.stderr.strip()[-400:]}")
        return r.stdout

    def index(self, root: Path) -> dict:
        db = root / ".gitmark" / "index.db"
        if db.exists():
            db.unlink()                      # engines have different schemas — always rebuild
        t = time.perf_counter()
        out = self._run(root, "index")
        m = re.search(r"(\d+)\s+(?:файл|files?)", out)
        return {"files": int(m.group(1)) if m else None, "index_s": time.perf_counter() - t}

    def search(self, root: Path, q: str, k: int) -> list:
        res = json.loads(self._run(root, "search", q, "-k", str(k), "--json", *self.extra) or "[]")
        seen, out = set(), []
        for r in res:                        # engines return chunks — collapse to files, keep order
            if r["path"] not in seen:
                seen.add(r["path"])
                out.append(r["path"])
        return out[:k]


# ─────────────────────────── scoring ───────────────────────────
def rank_of(found: list, gold: list) -> int | None:
    for i, p in enumerate(found, 1):
        if p in gold:
            return i
    return None


def summarize(rows: list, k: int) -> dict:
    n = len(rows) or 1
    ranks = [r["rank"] for r in rows]
    return {
        "n": len(rows),
        "hit@1": sum(1 for x in ranks if x == 1) / n,
        "hit@5": sum(1 for x in ranks if x and x <= 5) / n,
        f"mrr@{k}": sum(1 / x for x in ranks if x) / n,
        "lat_ms": 1000 * sum(r["lat"] for r in rows) / n,
    }


def run(repos: dict, qas: dict, engines: list, k: int) -> dict:
    results = {"k": k, "engines": {}}
    for eng in engines:
        per_q, per_repo = [], {}
        for name, root in repos.items():
            info = eng.index(root)
            per_repo[name] = info
            for line in Path(qas[name]).read_text("utf-8").splitlines():
                if not line.strip():
                    continue
                item = json.loads(line)
                t = time.perf_counter()
                try:
                    found = eng.search(root, item["q"], k)
                except Exception as e:      # an engine crash counts as a miss, but is reported
                    print(f"  ! {eng.name} {item['id']}: {e}", file=sys.stderr)
                    found = []
                lat = time.perf_counter() - t
                per_q.append({"repo": name, "id": item["id"], "kind": item.get("kind", "?"),
                              "q": item["q"], "gold": item["gold"], "found": found[:5],
                              "rank": rank_of(found, item["gold"]), "lat": lat})
        by = defaultdict(list)
        for r in per_q:
            by["ALL"].append(r)
            by["kind:" + r["kind"]].append(r)
            by["repo:" + r["repo"]].append(r)
        results["engines"][eng.name] = {
            "summary": {key: summarize(rows, k) for key, rows in sorted(by.items())},
            "repos": per_repo,
            "questions": per_q,
        }
    return results


def print_table(res: dict):
    k = res["k"]
    engines = list(res["engines"])
    keys = list(next(iter(res["engines"].values()))["summary"])
    metrics = ["hit@1", "hit@5", f"mrr@{k}"]
    w = max(len(x) for x in keys) + 2
    head = "".join(f"{e:>24}" for e in engines)
    print(f"\n{'slice':<{w}}{'n':>4}{head}")
    print(f"{'':<{w}}{'':>4}" + "".join(f"{'h@1  h@5  mrr':>24}" for _ in engines))
    for key in keys:
        n = res["engines"][engines[0]]["summary"][key]["n"]
        cells = ""
        for e in engines:
            s = res["engines"][e]["summary"][key]
            cells += f"{s['hit@1']:>14.2f}{s['hit@5']:>5.2f}{s[metrics[2]]:>5.2f}"
        print(f"{key:<{w}}{n:>4}{cells}")
    print(f"\n{'engine':<10}{'search ms':>11}{'index s / files per repo'}")
    for e in engines:
        r = res["engines"][e]
        idx = "  ".join(f"{n}:{v['index_s']:.1f}s/{v['files']}" for n, v in r["repos"].items())
        print(f"{e:<10}{r['summary']['ALL']['lat_ms']:>9.0f}  {idx}")


def main(argv=None):
    ap = argparse.ArgumentParser(description=__doc__, formatter_class=argparse.RawDescriptionHelpFormatter)
    ap.add_argument("--repo", action="append", default=[], help="NAME=PATH")
    ap.add_argument("--qa", action="append", default=[], help="NAME=qa.jsonl")
    ap.add_argument("--engine", action="append", default=[],
                    help="'grep' or NAME=path/to/gitmark.py[,extra-search-args]")
    ap.add_argument("-k", type=int, default=10)
    ap.add_argument("--json", help="write full results (per question) here")
    a = ap.parse_args(argv)
    repos = {n: Path(p).resolve() for n, p in (x.split("=", 1) for x in a.repo)}
    qas = dict(x.split("=", 1) for x in a.qa)
    missing = set(repos) ^ set(qas)
    if missing:
        ap.error(f"--repo/--qa mismatch: {sorted(missing)}")
    engines = []
    for spec in a.engine or ["grep"]:
        if spec == "grep":
            engines.append(GrepEngine())
            continue
        name, _, rest = spec.partition("=")
        script, *extra = rest.split(",")
        engines.append(CliEngine(name, Path(script).resolve(), [x for x in extra if x]))
    res = run(repos, qas, engines, a.k)
    print_table(res)
    if a.json:
        Path(a.json).parent.mkdir(parents=True, exist_ok=True)
        Path(a.json).write_text(json.dumps(res, ensure_ascii=False, indent=1), "utf-8")
        print(f"\n→ {a.json}")


if __name__ == "__main__":
    main()

# GitMark ontology — a knowledge model over code

> Rules for **how to maintain** a knowledge base (not just how to search it). The idea
> is borrowed from **Palantir's Ontology** (Gotham/Foundry): an organization is modeled
> as a graph of typed **objects**, their **properties**, and the **links** between them —
> a "digital twin." GitMark applies the same model to project documentation: every `.md`
> document is an **object** with a **type** and **properties**, and markdown links are
> **typed links**. The result is an ontology not of data, but of **knowledge over code**.

Why: so the KB doesn't rot into a pile of files. Type + properties + links make it
navigable, checkable (via the linter), and graphable (`gitmark map`).

## Semantic layer — Objects, Properties, Links

### Object types (`node_type`)

Each document has exactly one `node_type` — its "table" in the ontology.

| node_type | what it is | lives in |
|---|---|---|
| `service` | overview/index of one service/component | `docs/services/<svc>/README.md` |
| `reference` | cross-cutting spec (not about one service) | `docs/reference/` |
| `runbook` | operational procedure ("how to X") | `docs/ops/` |
| `gotcha` | a pitfall + how to avoid it | `docs/ops/` |
| `decision` | an architectural/product decision (ADR) | `docs/decisions/` |
| `plan` | a plan/design before implementation | `docs/plans/` |
| `guide` | how to use something (clients, public API) | varies |
| `report` | a one-off dated analysis/audit | `docs/reviews/` |
| `index` | a folder's table of contents | any `README.md` |

Rule: if unsure, a spec is `reference`, a how-to is `guide`. Add a new type only if
none fit and there will be ≥3 such documents.

### Properties (frontmatter)

YAML frontmatter at the top of the file — the "columns" of the object row.

```yaml
---
node_type: service          # REQUIRED — one of the table above (OKF: `type`)
title: Billing              # human-readable object name
description: "Who pays what and when: tariffs, trial, renewals and refunds in the billing service."
service: billing            # which service; use a sentinel (e.g. _platform) for cross-cutting
status: active              # active | draft | deprecated | archived
updated: 2026-06-06          # last meaningful edit (YYYY-MM-DD)
tags: [payments, api]       # free-form labels for search/grouping
generated: { by: claude-code/opus-5-5, at: 2026-06-06T10:00:00Z }   # who wrote it (OKF)
verified:                   # who confirmed it against reality (OKF) — never self-asserted
  - { by: human:vk, at: 2026-06-07T09:00:00Z }
stale_after: 2026-12-01T00:00:00Z   # perishable facts: re-check after this instant (OKF)
links:                      # typed links (see below), optional
  documents: [../../src/billing]
  depends_on: [../reference/architecture.md]
  supersedes: [old-billing.md]
---
```

Required: `node_type`. Strongly recommended for load-bearing docs
(`service|reference|runbook|plan|decision`): `title`, `description`, `service`, `status`,
`updated`. `description` is not decoration: it is indexed with extra weight, and on our
benchmark adding it lifted hit@1 from 0.77 to 0.83 (see
[decisions/okf-alignment.md](decisions/okf-alignment.md)).

### Trust and lifecycle (from OKF)

- **`generated`** `{by, at}` — who/what produced the current content. Actors:
  `<tool>/<version>` for agents (`claude-code/opus-5-5`), `human:<id>`, `process:<id>`.
- **`verified`** — list of `{by, at}` confirmations. The **trust tier** is derived, not
  stored: no `verified` → *unverified*; only machines → *machine*; any `human:` →
  *human*. An agent never writes a `human:` verification for itself.
- **`stale_after`** — absolute instant; past it the doc is *stale* (lint I8, demoted and
  labeled in search).

`gitmark query` answers questions over all of these without a database, e.g.
`query 'generated.by~claude' trust=unverified type=runbook`.

`service` is a **controlled vocabulary** you define for your project.

### Link types (`links`)

Links are markdown links `[text](path.md)`. The link type is declared by a key under
`links:`; inline links default to `relates_to`. `gitmark map` draws the graph from them.

| link type | meaning | direction |
|---|---|---|
| `documents` | this doc describes that code/service | doc → code |
| `depends_on` | read that one first to understand this | doc → doc |
| `supersedes` | replaces a stale document | new → old |
| `relates_to` | adjacent topic (default for inline links) | doc ↔ doc |
| `implemented_by` | where it lives in code | doc → source file |
| `part_of` | belongs to a larger index | doc → index |

The doc→code link (`documents`/`implemented_by`) is what makes this an ontology **over
code**: a document is explicitly tied to the files/component it describes.

## Kinetic layer — Actions (curation rules)

In Palantir, **Actions** sit on top of the semantics — what you can do with objects.
Here, Actions = the **curation procedures** a human/agent runs (see `kb-curate` skill):
CREATE → classify, place, frontmatter, link, index. UPDATE → bump `updated`/`status`.
DEPRECATE → `status` + `supersedes`. LINK → no orphans. REINDEX → `gitmark index`.

## Invariants (checked by `gitmark lint`)

- **I1.** Every load-bearing doc has frontmatter with a valid `node_type`.
- **I2.** `node_type`/`service`/`status` values are within their vocabularies.
- **I3.** No orphans: a load-bearing doc has ≥1 incoming or outgoing link.
- **I4.** No broken links (a markdown link to a missing file).
- **I5.** Every `docs/**` folder has a `README.md` index.
- **I6.** A `supersedes` target has `status: deprecated|archived`.
- **I7.** A `documents`/`implemented_by` target (code path) exists.
- **I8.** `stale_after` has not passed.

Vocabularies are extensible per project in this file's own frontmatter
(`vocab: {service: […], node_type: […], status: […], link: […]}`); without
`vocab.service`, the service vocabulary is derived from folder names.

## Relation to the Open Knowledge Format (OKF)

OKF (Google, v0.2) standardizes the same idea — a folder of markdown concepts with YAML
frontmatter. OntoShip reads OKF bundles as-is and adds what OKF deliberately leaves out:

| | OKF | OntoShip |
|---|---|---|
| type key | `type` (free string) | `node_type` (controlled vocab) — `type` accepted |
| summary | `description` | `description` (same) |
| trust / lifecycle | `generated`, `verified`, `status`, `stale_after` | same fields; `stable` = `active` |
| links | untyped, meaning in prose | **typed** (`documents`, `depends_on`, `supersedes`…) incl. doc → code |
| folder index | `index.md` | `README.md` (`index.md` also accepted) |
| validation | consumers must tolerate anything | `gitmark lint` invariants I1–I8 |
| search / query | out of scope | `gitmark search` (FTS5) + `gitmark query` (frontmatter) |

## Why this, not a wiki/Notion

- **md+git** is already the source of truth. The ontology adds *structure on top* without
  changing the medium — frontmatter and links are plain markdown, readable in any viewer.
- The object/link graph gives Foundry-like navigation with no platform: `gitmark map`
  renders it from the same files.
- Types + invariants keep the KB from degrading into a pile as it grows — the exact pain
  Palantir's ontology solves for data, applied here to knowledge over code.

Prototype model: [Palantir Ontology overview](https://www.palantir.com/docs/foundry/ontology/overview)
· [Core concepts](https://www.palantir.com/docs/foundry/ontology/core-concepts).

# Decision: OKF-compatible frontmatter + a benchmark for search

## Context

Two outside signals in autumn 2026 pointed the same way: Google published the **Open
Knowledge Format** (a folder of markdown with YAML frontmatter, plus trust/provenance/
lifecycle fields), and a widely read post argued that plain text + frontmatter outlives
every vector/graph "company brain" — frontmatter turns a folder into something an agent
can *query* (who attended, what is verified, by whom) without a database.

Running gitmark 0.1 over seven real project KBs showed it did not live up to its own model:

- **Typed links were never parsed.** The frontmatter parser ignored indentation, so
  `links:` was always `{}` across ~300 docs that declare it; I3/I6 could not work and the
  graph had no link types.
- `lint` **crashed** on list-valued `service:` and kept YAML comments inside values.
- Discovery walked the filesystem: 5 271 vendored md files indexed in one repo (25 s),
  a docs copy used as test data outranked the real docs in another.
- Frontmatter was not indexed at all — no title/description boost, no type/status filter,
  deprecated docs ranked like live ones.

## Decision

1. **Read OKF frontmatter natively**: `type` = `node_type`, `description`, `generated` /
   `verified` (derived trust tier), `stale_after`, `status: stable`, root-relative links.
   Keep OntoShip's additions (typed links, controlled vocabularies, lint).
2. **Real YAML**: PyYAML when present, a stdlib subset parser otherwise (same output on
   our fixtures, tolerant of `title: a: b`).
3. **Index frontmatter** and rank per file: chunk bm25 + doc-level bm25 over
   title/description/tags/path + trigram phrase + fuzzy, fused with RRF; priors for
   typed docs, penalties for indexes/changelogs, deprecated and stale docs.
4. **Discover via git** (`ls-files -co --exclude-standard`) + `.gitmarkignore`.
5. **`gitmark query`** for structured questions over frontmatter, read straight from md.
6. **Measure, don't argue**: `bench/kbbench.py` — gold QA sets per repo, hit@1/hit@5/MRR.

## Results (198 questions, 7 real repos; QA sets private, harness in `bench/`)

| engine | hit@1 | hit@5 | MRR@10 |
|---|---|---|---|
| grep (agent without the skill) | 0.30 | 0.67 | 0.46 |
| gitmark 0.1 | 0.47 | 0.82 | 0.62 |
| **gitmark 0.2** | **0.69** | **0.93** | **0.80** |

By query kind (0.1 → 0.2, hit@1): paraphrase 0.43 → 0.64, keyword 0.60 → 0.80,
typo 0.47 → 0.75. Index time on the vendored repo: 25 s → 0.5 s.

**`description` experiment** (3 repos, 90 questions; descriptions added by an agent to a
mirror, nothing else changed):

| engine | hit@1 without → with | MRR without → with |
|---|---|---|
| grep | 0.29 → 0.41 | 0.47 → 0.56 |
| gitmark 0.1 | 0.47 → 0.57 | 0.65 → 0.71 |
| gitmark 0.2 | 0.77 → 0.83 | 0.85 → 0.89 |

The one-line summary helps *every* consumer, including plain grep — structure in plain
text pays off without any tooling. Hence `description` is now recommended for every
load-bearing doc (`kb-curate`).

Ranking weights were tuned on a dev split (odd questions) and checked on the held-out
even half; the tuned config moved test MRR 0.753 → 0.795, and the top dev configs were
within noise of each other. Most of the gain is structural (discovery, per-file fusion,
frontmatter fields), not weight-fiddling.

## Caveats

- QA sets and descriptions were written by an LLM from the docs themselves; absolute
  numbers are optimistic. Relative comparisons on the same set are the point.
- Search is still lexical. Paraphrases with no shared vocabulary remain the ceiling
  (hit@5 0.89); the skill tells the agent to reformulate (ru↔en, identifiers, synonyms).
- Not yet measured: end-to-end agent answers (with vs without the skill, tokens/turns).

## Consequences

- KB docs should carry `description`; agent-written docs carry `generated`; only real
  verifiers add `verified`.
- Every change to ranking must come with a `bench/` run; regressions are visible per repo
  and per query kind.

# Decision: what OntoShip is for

> ADR capturing an external review of OntoShip and the resulting positioning call.
> Recorded so the conclusion is enforced, not re-argued from scratch.

## Context

OntoShip drew a substantive review. The useful part, stripped of the argument:
the project is **not** a research contribution and **not** a new search method — it is an
opinionated engineering product in three layers, with value spread unevenly across them:

1. **KB** — markdown as source of truth + regenerated artifacts (index / HTML / graph).
   Simple, honest, deterministic.
2. **Search** (FTS5 + trigram) — the weakest layer on the merits. On semantic recall a
   vector index wins. This is an accepted ceiling, not an edge.
3. **Workflow** — `dev-flow` (spec → worktree → review → ship) + `destructive-guard`.
   **This is the actual product**, and it's the layer the review never looked at.

The debate circled layer 2 (search); the real advantage is layer 3 — a **repeatable,
gated "operator + agent → PR" flow**. The wrong altitude was being defended.

## Decision

**OntoShip's goal: a tool that lets the team transfer the operating method for building
with AI agents.** It is internal **team enablement / experience-transfer**, not OSS-for-stars
and not sellable IP.

Concretely, OntoShip exists so an operator (teammate, or someone receiving a handed-off
"vibecoded" project) can pick up a repo and drive work to a PR with an agent — the way the
author would — without the author in the loop. The KB is the substrate that makes this
possible (a deterministic md source any human or agent can read); the dev-flow is the
method being transferred.

### Positioning consequences

- **Sell it as a ship-flow + operator-handoff over plain markdown — not as a search engine.**
- Layer 1 (md-as-truth + regeneration) is the honest architectural foundation: the source
  is deterministic; only the curator *agent* on top is non-deterministic. Keep it.
- Layer 2 (FTS5): state the boundary plainly — "good enough for ~hundreds of docs with an
  agent as the consumer." Don't claim search superiority.
- Layer 3 (dev-flow + guard) is where investment and the story go.

## What is genuinely strong (keep leaning on it)

- **Radical simplicity as an operational property** (zero-dep / offline / stdlib /
  deterministic) — lets the tool drop into any client repo, any CI, any operator's hands
  with no model or GPU. Directly serves the handoff use-case.
- **md-as-source-of-truth + regeneration** — clean answer to "non-deterministic source of
  truth": the source is deterministic; only the curator agent is not.
- **Proof by existence** — products maintained with this approach. For an engineering tool
  this is valid fitness-for-purpose evidence (survival test), not salesmanship.

## Valid criticism to address (accepted)

1. **No defined/measured metric** — the #1 gap. Without it there's no optimization target.
   → see [metrics.md](metrics.md). Reframed around *transfer*, not search quality.
2. **No related-works / positioning** — vs graphify / OKF / agents.md / skills. Add to
   README (convergent evolution, when-to-use). *Lower priority given the internal goal,
   but still the honest framing.*
3. **Structure is manual** — an AST-scaffold (skeleton derived from code, agent writes the
   prose) would close this and matches the "let the agent do everything" intent.
   → prototype `gitmark scaffold`.
4. **FTS5 ceiling is real** — fine at ~100 docs + agent consumer; declare it as a conscious
   boundary, not "best in class."

## Where the review overreached (noted, not adopted)

Treated the optional ontology as mandatory; called `lint` overhead (it's invariant
enforcement); "FTS = a crutch for bad structure" is too absolute; and judged an engineering
tool by scientific falsifiability (category error). Strong on the merits, but reviewed one
layer and hung the verdict on the whole.

## Next actions (priority order)

1. **Define + measure the transfer metric** on 3 projects — see [metrics.md](metrics.md).
2. **Related-works** paragraph in README (graphify / OKF / agents.md / skills).
3. **AST-scaffold prototype** (`gitmark scaffold`) so structure is derived, not hand-authored.

# OntoShip architecture

OntoShip is a **Claude Code marketplace** (`ontoship`) that ships **two plugins**:

- **`gitmark`** — a markdown + git knowledge base with FTS5 search, a self-contained
  HTML graph, an ontology linter, *and* the spec-driven **dev-flow** built on top of it.
- **`destructive-guard`** — a `PreToolUse` Bash safety hook that intercepts destructive
  commands and forces a y/n confirmation.

The marketplace manifest (`.claude-plugin/marketplace.json`) registers both; the root
`.claude-plugin/plugin.json` defines the `gitmark` plugin, and
`destructive-guard/.claude-plugin/plugin.json` defines the guard.

## Core principle: md+git is the source of truth

The thing you and your AI assistant read is **plain markdown**, in any editor. Everything
**derived** is **regenerated** from that markdown, so git stays clean and there is no
service, database, embeddings, or vendor to run:

| artifact | derived from | lives in | regenerated by |
|---|---|---|---|
| `index.db` (SQLite FTS5) | the `.md` files | `.gitmark/` (gitignored) | `gitmark index` |
| `docs-map.html` (tree + graph) | the `.md` files + their links | wherever you point it | `gitmark map` |

The entry point is `CLAUDE.md` / `AGENTS.md`; every folder's `README.md` is its index.
Because derived artifacts never live in git, the KB can never drift from its index — you
just re-run the CLI.

## Repo layout

```
ontoship/
├─ .claude-plugin/
│  ├─ marketplace.json        ← marketplace "ontoship": 2 plugins
│  └─ plugin.json             ← the gitmark plugin
├─ commands/                  ← slash commands (the user-facing verbs)
│  ├─ kb.md        (/kb)       search the KB
│  ├─ kb-map.md    (/kb-map)   build the HTML graph
│  ├─ doc.md       (/doc)      compose/update ONE doc
│  ├─ onto-doc.md  (/onto-doc) build the WHOLE KB (fan-out curators)
│  └─ ship.md      (/ship)     run the dev-flow
├─ skills/                    ← the capabilities the commands invoke
│  ├─ kb-search/  SKILL.md + gitmark.py   ← the CLI engine (zero-dep, stdlib)
│  ├─ kb-curate/  SKILL.md                ← curation / ontology rules
│  └─ dev-flow/   SKILL.md                ← the ship pipeline
├─ destructive-guard/         ← the second plugin
│  ├─ .claude-plugin/plugin.json
│  ├─ hooks/                  ← the PreToolUse Bash hook
│  └─ tests/
└─ docs/                      ← the KB itself (dogfooded)
   ├─ ontology.md             ← the knowledge model (types, links, invariants)
   ├─ services/               ← per-component READMEs (gitmark-cli, dev-flow, …)
   └─ reference/              ← cross-cutting specs (this file, commands.md)
```

## How the pieces connect

A user types a slash command; the command delegates to a skill; the skill calls the
`gitmark` CLI engine, which reads and writes the markdown KB:

```
 user
   │  /kb · /kb-map · /doc · /onto-doc · /ship
   ▼
 commands/*.md ──────────────► skills/
   │                              ├─ kb-search ── gitmark.py ──► .md KB ──► .gitmark/index.db
   │                              │   (the CLI engine)               └──► docs-map.html
   │                              ├─ kb-curate  (ontology rules) ──► writes/edits .md
   │                              └─ dev-flow   (ship pipeline) ────► uses kb-curate for specs
   ▼
 destructive-guard (PreToolUse hook)  ── guards every Bash command, in parallel
```

- **`kb-search`** is the heart: `skills/kb-search/gitmark.py` is the single
  Python-stdlib CLI (`index`, `search`, `map`, `serve`, `stat`, `lint`, `version`).
  `/kb` and `/kb-map` are thin wrappers over it.
- **`kb-curate`** holds the curation rules derived from
  [`ontology.md`](../../ontology.md) — what `node_type` a doc gets, where it lives, its
  frontmatter and typed links. `/doc` wraps it for one doc; `/onto-doc` fans out a
  `kb-curate` curator agent per area to build the whole KB, then lints + indexes + maps.
- **`dev-flow`** is the spec-driven loop (`/ship`): research → tasks → goal → spec (written
  as markdown via `kb-curate`) → isolated git worktree → implement → tests → independent
  review → dev-tests → prod-tests → ship (MR → `dev` → `main`). Its specs become KB docs,
  closing the loop back into the same markdown.
- **`destructive-guard`** is orthogonal to the KB: it runs as a `PreToolUse` Bash hook on
  every command, token-parsing for destructive verbs (`rm`, `git reset --hard`,
  `docker rm -v`, SQL `DROP`/`TRUNCATE`) and forcing y/n confirmation even under
  `bypassPermissions`.

  [dev-flow](../services/dev-flow/README.md) ·
  [destructive-guard](../services/destructive-guard/README.md).

# OntoShip slash commands

Reference for the slash commands shipped by the **OntoShip** Claude Code plugin. Each
command is a thin `commands/*.md` definition that drives a skill or engine. Two families:

- **KB curation & search** — `/kb`, `/kb-map`, `/doc`, `/onto-doc` — drive the GitMark
  CLI (`skills/kb-search/gitmark.py`) and the `kb-curate` ontology rules.
- **Dev-flow** — `/ship` — drives the gated `dev-flow` pipeline from idea to production.

`${CLAUDE_PLUGIN_ROOT}` below resolves to the installed plugin directory; the GitMark CLI
is `${CLAUDE_PLUGIN_ROOT}/skills/kb-search/gitmark.py`.

## Summary

| Command | What it does | Args | Drives |
|---|---|---|---|
| `/kb` | Search the project KB (all `.md`) and answer from the top hits; structural questions go to `query` | `<query>` (empty → stat + usage) | GitMark CLI `search` / `query` / `stat` / `index` |
| `/kb-map` | Build a self-contained HTML map of the KB (tree + link graph) | `[output-path]` (default `docs-map.html`) | GitMark CLI `map` / `index` |
| `/doc` | Compose or update **one** KB document per the ontology | `<topic>` | `kb-curate` skill + GitMark CLI |
| `/onto-doc` | Build (or rebuild) the **whole** KB by fanning out curator agents | `[scope]` (empty → whole repo) | `kb-curate` skill via `Task` fan-out + GitMark CLI |
| `/ship` | Take a feature/fix from idea to production through the gated pipeline | `<change description>` | `dev-flow` skill |

---

## `/kb` — search the knowledge base

- **Definition:** `commands/kb.md` · **Allowed tools:** `Bash(python3:*)`
- **What it does:** searches every `.md` git sees in the project (docs/, READMEs, etc.) via
  GitMark (per-file ranking: section bm25 + title/description/tags + trigram/fuzzy, RRF
  fusion; typed docs boosted, deprecated/stale demoted), then summarizes the top hits and
  answers from the 1–2 most relevant files. Structural questions ("which decisions are
  active", "plans per service") are answered with `gitmark.py query` over frontmatter.
- **Args:** `$ARGUMENTS` = the search query. **Empty** → runs `gitmark.py stat` and shows
  the `/kb <query>` syntax instead of searching.
- **Behavior:**
  1. Empty query → `gitmark.py stat` + usage hint.
  2. Otherwise: refresh index if needed (`gitmark.py index`), then
     `gitmark.py search "$ARGUMENTS" -k 8`, summarize hits as `file:line` (no full
     snippets), and open the most relevant files to answer.
- **Drives:** GitMark CLI (`kb-search` skill).

## `/kb-map` — render the KB graph

- **Definition:** `commands/kb-map.md` · **Allowed tools:** `Bash(python3:*)`
- **What it does:** generates a self-contained HTML map of the knowledge base — a
  collapsible tree, rendered markdown, and a force/radial link graph built from the typed
  links in frontmatter.
- **Args:** `$ARGUMENTS` = output path. **Default `docs-map.html`** when omitted.
- **Behavior:**
  1. Refresh the index: `gitmark.py index`.
  2. Build the map: `gitmark.py map -o "${ARGUMENTS:-docs-map.html}"`.
  3. Report the output path and offer to `open <path>` or `serve` it.
- **Drives:** GitMark CLI `map` (`kb-search` skill).

## `/doc` — compose/update one KB document

- **Definition:** `commands/doc.md` · **Allowed tools:** `Bash(python3:*)`
- **What it does:** composes or updates a **single** KB document for a topic, following the
  `kb-curate` ontology (node_type, frontmatter, typed links, folder README index).
- **Args:** `$ARGUMENTS` = the topic/document subject.
- **Behavior (per `kb-curate`):**
  1. **Search first** (`gitmark.py search`) — if the topic exists, edit that doc; never
     create a duplicate.
  2. **Pick a `node_type`** (`service` · `reference` · `runbook` · `gotcha` · `decision` ·
     `plan` · `guide` · `report` · `index`) and the right folder.
  3. **Write frontmatter** — `node_type`, `title`, `description`, `service`,
     `status: active`, `updated: <today>`, `generated` (agent-written).
  4. **Add ≥1 typed link** (to code or a sibling doc) — no orphans.
  5. **Add a line to the folder `README.md`** index.
  6. **Lint + reindex** — `gitmark.py lint` then `gitmark.py index`.
- **Drives:** `kb-curate` skill + GitMark CLI. Wraps `gitmark:doc`.

## `/onto-doc` — build the whole KB

- **Definition:** `commands/onto-doc.md` · **Allowed tools:** `Bash(python3:*)`, `Task`
- **What it does:** builds (or rebuilds) the **entire** OntoShip KB for the repo by
  surveying the codebase and fanning out `kb-curate` curator subagents per area, then
  linting, indexing, and mapping. Used to bootstrap or rebuild a project's whole KB.
- **Args:** `$ARGUMENTS` = scope hint. **Empty** → whole repo; or a subset
  (e.g. `services/api services/billing`, or "only reference docs").
- **Behavior:**
  1. **Survey** the repo (dirs, services, entry points, build/deploy, existing docs);
     check coverage with `gitmark.py stat`.
  2. **Decompose** into doc areas — service READMEs (`service`), cross-cutting specs
     (`reference`), ops procedures (`runbook`/`gotcha`), decisions (`decision`).
  3. **Dispatch curators (fan-out)** — one `Task` subagent per area, each following
     `kb-curate` on its slice only (search first, pick node_type + folder, frontmatter,
     ≥1 typed link, README index line). Independent areas run in parallel, scoped to avoid
     collisions.
  4. **Entry point + indexes** — ensure `CLAUDE.md`/`AGENTS.md` exists, `docs/README.md`
     is the master index, every folder has a README index.
  5. **Verify & derive** — `gitmark.py lint` (fix broken links/orphans/missing
     frontmatter), then `gitmark.py index`, then `gitmark.py map -o docs-map.html`.
  6. **Report** — docs created/updated, coverage before→after, lint result, map path,
     areas needing a human decision.
- **Drives:** `kb-curate` skill via `Task` fan-out + GitMark CLI. Wraps `gitmark:onto-doc`.

## GitMark CLI subcommands (0.2)

| Subcommand | What it does |
|---|---|
| `index` | rebuild `.gitmark/index.db` (chunks, frontmatter, typed links) |
| `search "<q>" [--type --status --service]` | ranked, one result per file, with type/status/trust labels |
| `query key=val … [--count-by key] [--fields …]` | structured questions over frontmatter, straight from md |
| `lint [--json]` | ontology invariants I1–I8 |
| `health [--json]` | KB scorecard: typed %, description %, typed links, orphans, trust, stale, duplicates |
| `map` / `serve` / `stat` / `version` | HTML graph, local server, index stats, version |

## `/ship` — run the dev-flow

- **Definition:** `commands/ship.md` · **Allowed tools:** none declared (uses default
  toolset)
- **What it does:** drives a feature/fix from idea to production through the gated
  OntoShip dev-flow pipeline.
- **Args:** `$ARGUMENTS` = the change to ship (feature/fix description).
- **Pipeline (per the `dev-flow` skill, end to end):**
  1. **Research** — understand from facts (logs, traces, code); reproduce before fixing.
  2. **Tasks** — decompose into tracked tasks.
  3. **Goal** — one clear goal + a "done" criterion.
  4. **Spec** — write it as markdown in the KB via `kb-curate` (node_type, frontmatter,
     typed links `documents:[src/…]`); search the KB first — don't duplicate.
  5. **Isolate** — work in a dedicated `git worktree`.
  6. **Implement** — code to the spec.
  7. **Tests** — write/adjust unit + E2E.
  8. **Independent review** — run an independent model (e.g. Codex CLI, read-only) over
     the diff.
  9. **Dev-tests** — MR + commits into `dev`; run the full suite. Red → fix, don't merge.
  10. **Prod-tests** — E2E/smoke against the real prod contour.
  11. **Ship** — merge `dev → main` and deploy (build-before-stop + healthcheck-poll).
- **Gates:** tests + independent review are not skippable; the spec is the carrier of
  knowledge, not a throwaway ticket.
- **Drives:** `dev-flow` skill.

# Metrics — what OntoShip should be measured by

> The #1 gap from review: no defined, measured metric → no optimization target.
> Per the [positioning decision](../decisions/ontoship-positioning.md), OntoShip's goal is
> **team experience-transfer for AI-agent development**, so the metrics measure *transfer
> and operator autonomy* — not search quality.

`status: draft` until baselines are collected on 3 projects.

## Primary metrics

Measure on **3 real projects** (the ones already maintained with this approach):

| Metric | Definition | Why it matters |
|---|---|---|
| **Operator onboarding time** | Calendar time from "new operator gets the repo" → their first merged PR, *without the author in the loop* | The core transfer claim: can someone pick up the method and ship? |
| **Autonomous-PR rate** | % of tasks an operator drives to PR without the author intervening | Measures whether the *method* transferred, not just one task |
| **Feature → PR time** | Time from task defined → PR opened, via the gated dev-flow | Throughput of the flow itself |

## Secondary / supporting

- **Time-to-first-answer in the KB** — operator finds the relevant doc via `/kb` instead of
  asking the author (proxy for KB self-sufficiency).
- **Re-derivation cost** — wall-clock to rebuild index + map after edits (keeps the
  "derived is cheap" promise honest).
- **Lint cleanliness** — broken links / orphans over time (KB rot indicator).

## How to collect (lightweight)

- Onboarding time / autonomous-PR rate: track per operator per project in a simple log
  (date repo handed over, date of first independent PR, tally of author interventions).
- Feature → PR time: read it off git/PR timestamps; the dev-flow already produces a PR.
- KB self-sufficiency: spot-check — did the operator ask the author something the KB
  already answers?

## What this is NOT

Not search precision/recall, not embedding-quality benchmarks. The review's pull toward
"prove the search" is the wrong target for an internal transfer tool — see the
[positioning decision](../decisions/ontoship-positioning.md).

# destructive-guard

> Lives in its own repo since the split:
> [github.com/vakovalskii/destructive-guard](https://github.com/vakovalskii/destructive-guard).
> Paths below are relative to that repo.

A Claude Code **PreToolUse hook** that intercepts destructive shell commands and turns
them into an interactive **y/n confirmation** before they run. It is a single
stdlib-only Python script — no dependencies. Source:
[confirm-destructive.py](https://github.com/vakovalskii/destructive-guard/blob/main/hooks/confirm-destructive.py).

The guard never *blocks* a command outright (no `exit 2`); instead it returns
`permissionDecision: "ask"`, so Claude Code surfaces a y/n prompt. On safe commands it
exits silently (`exit 0`, no decision) and lets normal permission rules decide.

## How the hook is wired

[hooks.json](https://github.com/vakovalskii/destructive-guard/blob/main/hooks/hooks.json) registers one hook:

- Event: **`PreToolUse`**
- Matcher: **`Bash`** (only Bash tool calls are inspected)
- Command: `python3 "${CLAUDE_PLUGIN_ROOT}/hooks/confirm-destructive.py"`
- Timeout: `5` seconds

The hook reads the tool-call JSON from stdin, pulls `tool_input.command`, runs `detect()`
on it, and — if destructive — emits an `ask` decision as JSON on stdout. Empty / unparsable
input proceeds silently.

## What it guards (exact detection)

Detection is **token-based**: the command is split on `; && || | & ( ) \`` and the *first
token* of each simple command is examined. Leading `VAR=val` assignments and prefixes
(`sudo`, `command`, `time`, `env`, `nohup`, `builtin`, `exec`, `then`, `do`, `else`,
`{`, `(`, `!`) are skipped. The program name is path-stripped and a leading
backslash-escape is removed (`\rm` → `rm`). Because only the leading token is matched,
look-alikes like `perform`, `transform`, `terraform` are **not** flagged.

Each detection carries a **severity** — `CRITICAL` or `ORDINARY` — used for the
bypassPermissions tiering described below.

| Category | Patterns detected | Severity |
|---|---|---|
| File deletion | `rm` (severity computed, see below); `shred`, `srm`, `dropdb` | CRITICAL |
| File deletion | `rmdir`, `unlink`, `truncate` | ORDINARY |
| find-based delete | `find … -delete`, `find … -exec\|-execdir\|-ok\|-okdir rm\|unlink\|shred\|srm\|rmdir` | CRITICAL |
| git | `git rm` | ORDINARY |
| git | `git clean` (CRITICAL if `-f`/`--force`, else ORDINARY); `git reset --hard`; `git push --force`/`-f`/`+refspec`; `git branch -D` | CRITICAL (clean conditional) |
| docker / podman | `docker rm`, `docker rmi`, `docker image\|network\|container rm` | ORDINARY |
| docker / podman | `docker volume rm`; `docker volume\|image\|system\|network\|container\|builder prune`; `docker compose down -v\|--volumes` | CRITICAL |
| docker-compose | `docker-compose down -v\|--volumes` | CRITICAL |
| SQL | `DROP TABLE\|DATABASE\|SCHEMA`, `TRUNCATE`, `DELETE FROM` — only when a DB client (`psql`, `mysql`, `mariadb`, `mongosh`, `mongo`, `clickhouse-client`, `clickhouse`, `sqlite3`, `dropdb`) appears in the command | CRITICAL |

### `rm` severity logic (`_rm_severity`)

- **CRITICAL** if any target is a dangerous path: empty, `/`, `~`, `*`, `.`, `..`, or
  starts with `/` `~` `$`, or contains `*` or `..`.
- Otherwise, if recursive (`-r`/`-R`/`--recursive`): **CRITICAL**, *unless* every target is
  a regenerable directory — then **ORDINARY**. Regenerable set: `build`, `dist`,
  `node_modules`, `.next`, `target`, `coverage`, `out`, `.cache`, `tmp`, `.pytest_cache`,
  `__pycache__`, `.turbo`, `.parcel-cache`, `.nuxt`, `.svelte-kit`, `.gradle`, `bin`, `obj`
  (targets normalized by stripping trailing `/` and leading `./`).
- Otherwise (non-recursive single-file `rm`): **ORDINARY**.

### Closed bypasses (red-team hardened)

- `\rm`, `\git` — leading backslash-escape stripped from the program name.
- `git -C path …`, `git -c k=v …`, `git --git-dir=… …` — leading git global options
  (incl. value-taking `-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace`,
  `--super-prefix`, `--exec-path`) skipped before reading the subcommand.
- `docker --context prod rm`, `docker -H host rmi` — same global-option stripping for
  docker (`--context`, `-H`/`--host`, `--config`, `--log-level`/`-l`, TLS opts).
- `bash -c "rm …"`, `sh -c '…'`, `bash -lc "…"` — the `-c` script string is unquoted and
  re-analyzed recursively (depth-limited to 4; shells: `sh bash zsh dash ash ksh fish`).
- `… | xargs rm`, `xargs -0 rm` — the command xargs would run is parsed recursively
  (xargs value-opts like `-I -n -P -d …` skipped first).

### Explicitly NOT flagged

`>` redirects, `docker compose down` without `-v`, `git push --force-with-lease`, `mv`,
and destructive logic *inside* a file/script (`python x.py` / `os.remove`,
`node x.js` / `unlinkSync`, `psql -f file.sql`, `bash x.sh`) — the token parser does not
read file contents. These are left to Claude Code's built-in guard, deliberately, to keep
the signal-to-noise ratio high.

## Confirmation behavior

When a destructive command is detected, the hook prints a JSON decision:

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse",
  "permissionDecision": "ask",
  "permissionDecisionReason": "⚠️ Команда на удаление — подтвердите: <reason>"}}
```

Claude Code then shows a y/n prompt. Because this is an **explicit `ask`**, it survives
`bypassPermissions` — but with a **tier**:

- In `permission_mode == "bypassPermissions"`, the hook only raises the y/n prompt on
  **CRITICAL** detections; **ORDINARY** ones proceed silently (the user has explicitly
  opted into bypass for routine, reversible local deletions).
- In every other mode (`default`, etc.), **any** detection — CRITICAL or ORDINARY —
  raises the prompt.

### Sound / banner alert

On `ask`, `_alert()` fires a fire-and-forget notification (stdout stays JSON-only):

- A terminal **BEL** (`\a`) to stderr (visual-bell flash if enabled).
- On macOS only: an `osascript display notification` banner titled
  "🛡️ Команда на удаление" plus a system sound, and a duplicate `afplay` of the sound
  file (in case banner sounds are muted).
- Sound name configurable via `NDG_SOUND` (default `Funk`). Disable all alerts with
  `NDG_NOTIFY=0`.

## How it's tested

[tests/test_hook.py](https://github.com/vakovalskii/destructive-guard/blob/main/tests/test_hook.py) is a stdlib-only
`unittest` suite that runs the real hook as a subprocess, feeds it JSON payloads, and
asserts the returned `permissionDecision`. Alerts are silenced via `NDG_NOTIFY=0`, so the
tests are safe and cross-platform. Coverage:

- `test_destructive_asks` — ~45 `ASK_CASES` spanning every category plus the closed
  bypasses (backslash, `git -C`, `bash -c`, `xargs`, docker global opts, etc.).
- `test_safe_proceeds` — `PROCEED_CASES` confirming look-alikes (`perform`/`terraform`),
  `git push --force-with-lease`, `compose down` without `-v`, redirects, `mv`, safe
  `bash -c`/`xargs`, etc. proceed silently.
- `test_empty_command_proceeds` — empty command proceeds.
- `test_bypass_critical_still_asks` — `BYPASS_CRITICAL` cases still prompt under
  `bypassPermissions`.
- `test_bypass_ordinary_proceeds_but_asks_default` — `BYPASS_ORDINARY` cases proceed
  silently under bypass but prompt in `default`.
- `test_manifests_valid_json` / `test_marketplace_source_points_to_plugin` — validate the
  plugin manifests and marketplace wiring.

Run: `python3 tests/test_hook.py` (or `python3 -m unittest -v`).

# dev-flow — spec-driven ship pipeline

`dev-flow` is OntoShip's gated pipeline for taking a feature or fix from idea to
production with an AI agent, fast and safely — typically **40 minutes to 2 hours** end
to end. The defining ideas: the **spec is plain markdown written into the KB**, the work
happens in an **isolated git worktree**, and **only green reaches prod**. The KB (the
GitMark knowledge base, see [kb-curate](../kb-curate/README.md)) is the carrier of
knowledge: onboarding, hand-off, and scaling all start from it, not from the code.

It is defined by the [`dev-flow` skill](../../../skills/dev-flow/SKILL.md) and invoked
through the [`/ship` command](../../../commands/ship.md).

## The gated pipeline

The pipeline is a sequence of stages where the later stages — review and tests — act as
**gates**: the change does not advance past a gate until it passes. Each stage produces
durable artifacts (tasks, a spec, a diff, test results) rather than throwaway state.

```
research → tasks → goal → spec → worktree → implement → tests
        → independent review → dev-tests → prod-tests → ship (MR → dev → main → prod)
```

### 1. Research
Understand the problem from **facts, not guesses**: read logs, traces, and the code
itself. Reproduce the bug or pin down the requirement before touching anything. This is
where wrong assumptions are cheapest to kill.

### 2. Tasks
Turn the research into a list of **tracked tasks with dependencies** so nothing gets
lost. Decomposition makes the scope explicit and orderable.

### 3. Goal
Crystallize **one clear goal** and a concrete **"done" criterion** from the tasks. A
single goal keeps the implementation honest and gives the gates something to check
against.

### 4. Spec
Write the spec as **markdown in the KB via [`kb-curate`](../kb-curate/README.md)** —
following the ontology: a `node_type`, frontmatter, and typed links
(`links.documents: [src/…]`) tying the spec to the code it governs. Search the KB first
(`kb-search`) so you don't duplicate an existing doc. The spec is **durable knowledge,
not a throwaway ticket**: searchable, linkable, and graphable (`gitmark map`). This is
where dev-flow builds directly on the GitMark KB — the spec becomes a first-class node
in the ontology rather than a comment that evaporates after merge.

### 5. Isolate (git worktree)
Do the work in a **dedicated `git worktree`**. `main` stays untouched, parallel agents
working on other changes don't collide, and rollback is just dropping the worktree.
Isolation is the default precisely so that experimentation is cheap and reversible.

### 6. Implement
Code to the spec inside the worktree, keeping doc↔code linked (`implemented_by`) so the
KB stays an accurate map of the codebase as the change lands.

### 7. Tests
Write or adjust **unit + E2E** tests for the feature. The test is **part of the
feature, not an afterthought** — it is the executable form of the "done" criterion.

### 8. Independent review (gate)
Run an **independent model** (e.g. Codex CLI, read-only) over the diff for logic and
security bugs before any rollout. A second model catches what the author's model
misses — on a real production codebase this pass caught **191 bugs** before they reached
prod. This is a gate because the cost of a missed logic/security bug in prod dwarfs the
cost of the review.

### 9. Dev-tests (gate)
Open an **MR with the commits into the `dev` branch** and run the **full suite** there.
Red → fix in the worktree, **don't merge**. The gate is the branch: nothing flows to
`main` until `dev` is green.

### 10. Prod-tests (gate)
Run **E2E / smoke tests against the real prod contour** — not only mocks or dev. Verify
behaviour where users actually live, because dev environments lie. This gate guards the
final merge.

### 11. Ship
Merge **`dev → main`** and deploy. Build the new image **before** stopping the old
container, then **poll the healthcheck** to measure real downtime. This ordering
minimizes the window where the service is unavailable.

## Git-flow

```
git worktree  →  MR + commits  →  dev branch (dev-tests)  →  main (prod-tests + deploy)  →  prod
```

## Why the gates

The gates — independent review, dev-tests, prod-tests — are deliberate and
non-negotiable. They are where bugs are caught before users see them; the 191-bug figure
comes specifically from the independent-review gate on a production codebase. Tests and
review are treated as **gates, not afterthoughts**, and behaviour is **verified on prod**,
not just dev.

## How it builds on the GitMark KB

The spec stage writes into the GitMark KB through `kb-curate`, so every shipped change
leaves behind an ontological document: typed, linked to its source via `documents` /
`implemented_by`, and discoverable through `kb-search` and `gitmark map`
(see [gitmark-cli](../gitmark-cli/README.md)). **md + git is the source of truth**;
everything derived — the search index, the graph — is regenerated. This is what lets
onboarding, hand-off, and scaling start from the KB rather than from reading the code.

## How a user invokes it

Run the [`/ship`](../../../commands/ship.md) command with a description of the change:

```
/ship <feature or fix description>
```

`/ship` drives the change through every stage of the pipeline, keeping the gates (tests +
independent review) and never skipping the spec. For a one-line change the stages can be
collapsed, but the gates stay — they are where the 191 bugs were caught.

## Principles

- **Spec = markdown + skills** — no ceremony, but ontological, so it stays searchable,
  linkable, and graphable.
- **Worktree isolation by default** — clean parallelism and clean rollback.
- **Tests and independent review are gates, not afterthoughts.**
- **Verify on prod**, not just dev.
- **md + git = source of truth**; everything derived is regenerated.

# gitmark CLI — KB search/index engine

`gitmark.py` is the search/index engine behind OntoShip. It treats the repo's markdown
(`docs/`, README files, any `*.md`) as a **md + git** knowledge base: markdown is the
source of truth, and everything derived — the search index, HTML map, graph — is
regenerated from it. The whole thing is pure Python stdlib (no third-party deps required;
`markdown` is an optional enhancement for the `map` renderer) and runs fully offline.

It enforces and operates over the OntoShip ontology (object types, properties, typed
links). For the model itself — `node_type`, frontmatter, link types, invariants I1–I6 —
see [ontology.md](../../ontology.md); this doc describes the engine, not the model.

Script: `skills/kb-search/gitmark.py`. The usage skill is `skills/kb-search/SKILL.md`.

## Subcommands

Invoked as `python3 gitmark.py <cmd>`. A global `--root <path>` overrides repo
auto-detection (see below); it precedes the subcommand. Defined in `main()`
(gitmark.py:556).

| cmd | what it does |
|---|---|
| `index [--force]` | (Re)build `.gitmark/index.db` — scans all `*.md`, chunks them, fills FTS tables + the `files`/`links`/`meta` tables. |
| `search "<q>" [-k N] [--json]` | Search the index: bm25 ∪ trigram ∪ fuzzy. Prints `path:line › heading [via]` + snippet; `-k` caps results (default 8); `--json` for machine output. |
| `map [-o OUT]` | Emit a single self-contained HTML file: collapsible tree + rendered markdown + radial link graph. Default out is `docs/docs-map.html`. |
| `serve [-p PORT]` | Local `http.server` over `docs/` (falls back to repo root) to view the map. Default port 8799. |
| `stat` | Index statistics: files, folders/areas, chunks, links, bytes, trigram on/off. |
| `lint [paths…] [--strict]` | Check ontology invariants I1–I6 (frontmatter/types/vocab/links/README/orphans). `--strict` exits 1 on any ERR. |
| `version` | Print `gitmark <VERSION>` (currently `0.1.0`, gitmark.py:33). |

Note: `index` accepts `--force` but the flag is currently inert — each `index` run already
deletes and rebuilds the tables unconditionally (gitmark.py:158-161).

## Root auto-detection

When `--root` is not given, the CLI walks up from the current working directory looking for
a `.git` directory and uses the first ancestor that has one; if none is found it falls back
to cwd. See `repo_root()` (gitmark.py:48-53). So `gitmark` can be run from anywhere inside
the repo and will resolve to the repo root.

A fixed set of directories is excluded from scanning regardless of root: `.git`,
`node_modules`, `.next`, `dist`, `build`, `__pycache__`, `.pytest_cache`, `_vendor`,
`.venv`, `venv`, `vendor`, and `.gitmark` itself (`EXCLUDE_DIRS`, gitmark.py:35-39). File
discovery is `iter_md()` (gitmark.py:56-60).

## Where the index lives

`.gitmark/index.db` under the repo root (`DB_REL`, gitmark.py:40). It is a derived cache and
should be gitignored — never edit it directly; edit the markdown and reindex. `search`/`stat`
require it to exist and tell you to run `gitmark index` if it's missing.

## How indexing works

`cmd_index()` (gitmark.py:139-198):

1. Read every non-excluded `*.md` under root into memory (used both for chunking and for
   link resolution against the set of known files).
2. For each file: derive a `title` (first `# H1`, else filename — `title_of`,
   gitmark.py:77-81) and an `area` (`area_of`, gitmark.py:63-74 — `docs/services/<svc>`
   gets its own group, otherwise `docs/<sub>`, `services/<svc>`, etc.).
3. **Chunking** — `chunk_md()` (gitmark.py:84-98) splits each file at markdown headings
   (`^#{1,6} …`). Each chunk is `(line_start, heading, body)`; this is the unit that gets
   indexed and the granularity at which search results point (`path:line`).
4. Each chunk is inserted into the `fts` table and (if available) the `tri` table.
5. **Links** — `LINK_RE` finds markdown links `[text](href)` (ignoring image links), and
   `resolve_link()` (gitmark.py:105-126) resolves each `href` to a known `.md` file. It
   strips `#anchors`, skips `http`/`mailto`, NFC-normalizes (so non-ASCII paths match),
   resolves relative/`../` paths via `posixpath.normpath`, and falls back to a unique
   basename match. Resolved `(src, dst)` pairs (deduped, excluding self-links) go into the
   `links` table. This populates the doc→doc edges the graph and the linter's orphan check
   use.
6. `meta` records whether trigram is available and the engine version.

**Trigram availability** is probed at runtime by trying to create an fts5 table with
`tokenize='trigram'` (`_has_trigram`, gitmark.py:130-136). If the SQLite build lacks the
trigram tokenizer, the `tri` table is skipped and search degrades to bm25-only. FTS5 itself
is mandatory — if SQLite has no FTS5 at all, `index` errors out with exit code 2
(gitmark.py:147-149).

## SQLite schema

Created in `cmd_index()`:

- `fts` — FTS5 virtual table, `tokenize='unicode61 remove_diacritics 2'`. Columns:
  `path UNINDEXED, heading, lineno UNINDEXED, body`. One row per chunk; the bm25 ranking
  table.
- `tri` — FTS5 virtual table, `tokenize='trigram'` (only if the trigram tokenizer exists).
  Same columns. Powers substring/fuzzy matching.
- `files(path TEXT PRIMARY KEY, title TEXT, area TEXT, size INT, chunks INT)` — one row per
  file (size is UTF-8 byte length).
- `links(src TEXT, dst TEXT)` — resolved doc→doc edges.
- `meta(k TEXT PRIMARY KEY, v TEXT)` — key/value: `trigram` (`"1"`/`"0"`) and `version`.

## How search ranks

`cmd_search()` (gitmark.py:227-292) merges up to three passes into one result set keyed by
`(path, lineno)`; earlier (stronger) passes win on collision, and results are sorted by the
combined score descending, then truncated to `k`.

1. **bm25 (exact terms)** — query words ≥2 chars become a prefix `OR` match
   (`"term"* OR …`, `_fts_match_query`, gitmark.py:202-204) against `fts`. Score is
   `-bm25(fts)` (full weight). `via: "bm25"`.
2. **trigram phrase (substring)** — the raw query as one quoted phrase against `tri`;
   matches exact substrings. Score weighted ×0.6. `via: "trigram"`. Only runs when the query
   is ≥3 chars and trigram is available.
3. **fuzzy (n-gram)** — handles typos, morphology, and Cyrillic. `_fuzzy_phrases()`
   (gitmark.py:207-224) breaks query words (≥4 chars) into overlapping 4-char windows;
   these are OR-matched against `tri`. A chunk is accepted only if its body contains at
   least `need` distinct windows (≈ceil(20% of windows), min 1 — gitmark.py:271), which
   filters chunks that merely share one common gram. Score weighted ×0.3. `via: "fuzzy"`.

Each pass returns a snippet via FTS5 `snippet(...,'»','«','…',14)` so the matched terms are
delimited in the output.

## Linting (ontology invariants)

`cmd_lint()` (gitmark.py:360-437) checks I1–I6 over `docs/**` using a stdlib mini
frontmatter parser (`parse_frontmatter`, gitmark.py:330-357 — no PyYAML). The controlled
vocabularies (`NODE_TYPES`, `SERVICES`, `STATUSES`, `LOAD_BEARING`, `LINK_KEYS`,
gitmark.py:312-319) are the lint source of truth and must stay in sync with
[ontology.md](../../ontology.md). Broken-link detection (I4) strips fenced/inline code first
(`strip_code`, gitmark.py:325-327) so example links in code blocks aren't flagged. ERR-level
issues: I1 (missing frontmatter/`node_type` on a load-bearing path), I2 (`node_type` out of
vocab), I4 (broken link). WARN-level: I2 service/status out of vocab, I3 (orphan — a
load-bearing doc with no in/out links and no `links:` block), I5 (a `docs/` folder with no
`README.md`), I6 (a `supersedes` target that isn't `deprecated`/`archived`).

## The map (HTML overview + graph)

`cmd_map()` (gitmark.py:441-537) produces one standalone HTML file (`_MAP_HTML` template,
gitmark.py:619+) with the data inlined as JSON: a collapsible per-area file tree, the
rendered markdown of each doc, and a radial link graph. The graph is laid out by BFS from an
entry node (`CLAUDE.md` → `README.md` → first file), with ring = distance-from-entry; it
supports drag, wheel-zoom, and clicking a node to open the doc. If the optional `markdown`
package is installed, docs render to HTML; otherwise they show as raw `<pre>` text (the CLI
prints a hint to `pip install markdown`).

## Usage examples

```bash
G="python3 skills/kb-search/gitmark.py"

$G index                       # build .gitmark/index.db
$G search "trigram ranking"    # bm25 + trigram + fuzzy; prints path:line + snippet
$G search "frontmater" -k 5    # typo-tolerant via fuzzy n-grams
$G search "ontology" --json    # machine-readable results
$G stat                        # files/folders/chunks/links/bytes · trigram on|off
$G lint                        # check ontology invariants over docs/
$G lint --strict               # exit 1 if any ERR
$G map -o out.html             # self-contained HTML overview + graph
$G serve -p 8799               # serve the map at http://127.0.0.1:8799/docs-map.html
```

# kb-curate — KB maintenance skill

`kb-curate` is the skill that keeps the markdown knowledge base healthy. It does not
search the KB or render it — it governs how docs are **added, edited, moved, and deleted**
so the collection stays a typed ontology instead of decaying into a pile of files.

The semantic model it enforces lives in [`docs/ontology.md`](../../ontology.md): every
`.md` document is a typed **object** (`node_type`) with **properties** (frontmatter) and
**typed links** — the Palantir-Foundry idea applied to documentation over code. This skill
is the **operational checklist** that puts that model into practice. Principle: *md+git is
the source of truth, with an ontology on top.*

## When it triggers

Apply the skill on any documentation mutation:

- **Add** a doc ("add a doc", "record a decision", "write a runbook").
- **Edit** a doc whose meaning changed, or whose status changed.
- **Move / reorganize** docs across folders.
- **Delete** a doc.

Before writing anything, search first (`gitmark.py search "<topic>"`). If the topic
already exists, **edit the existing doc** rather than creating a duplicate.

## The curation actions it codifies

These map to the kinetic layer ("Actions") of the ontology.

### CREATE (adding knowledge)

1. **Classify the `node_type`** — pick one type for the doc. Rule of thumb when unsure:
   a spec is `reference`, a how-to is `guide`.
2. **Place it in the right folder** — type drives location: service-specific →
   `docs/services/<svc>/`; cross-cutting → `docs/reference/`; ops procedure → `docs/ops/`;
   plan → `docs/plans/`; decision → `docs/decisions/`.
3. **Add frontmatter** — minimum `node_type`; for load-bearing docs also `title`,
   `service`, `status: active`, `updated: YYYY-MM-DD`.
4. **Add typed links** — at least one, to code (`documents` / `implemented_by`) or to a
   sibling doc (`depends_on` / `relates_to`). No orphans.
5. **Index it** — add a line to the folder's `README.md`: `- [Title](file.md) — hook`.

### UPDATE (editing)

- Meaning changed → bump `updated:`.
- Doc went stale → set `status: deprecated` and put `supersedes: [old.md]` on the
  replacement.
- Junk → delete it (git keeps the history).

### MOVE (reorganizing)

- `git mv` to preserve history, then **rewrite every link** to the doc and update the
  `README.md` indexes of both the source and destination folders.

### DEPRECATE

- Set `status` to `deprecated`/`archived` and record the replacement via `supersedes`.

### LINK — no orphans

- Every load-bearing doc must have at least one incoming or outgoing typed link.

### REINDEX — always at the end

```bash
python3 <plugin>/skills/kb-search/gitmark.py lint     # invariants I1–I6
python3 <plugin>/skills/kb-search/gitmark.py index    # rebuild search
```

`lint` flags missing/broken frontmatter, types outside the vocabulary, orphans, broken
links, and folders without a README. Fix until clean.

## The vocabularies it enforces (brief)

The skill never invents values — it draws from fixed vocabularies defined in the ontology:

- **`node_type`**: `service` · `reference` · `runbook` · `gotcha` · `decision` · `plan` ·
  `guide` · `report` · `index`.
- **Link types**: `documents` · `depends_on` · `supersedes` · `relates_to` ·
  `implemented_by` · `part_of`.
- **`status`**: `active` · `draft` · `deprecated` · `archived`.
- **`service`**: a controlled vocabulary defined per project.

See [`docs/ontology.md`](../../ontology.md) for the full type/link/property tables and the
`gitmark lint` invariants (I1–I6) — this README intentionally does not duplicate them.

## The loop

1. **Research** — understand from facts, not guesses: read logs, traces, and the code

2. **Tasks** — turn the research into a list of tracked tasks with dependencies. Nothing

3. **Goal** — crystallize one clear goal and the "done" criterion from those tasks.
4. **Spec** — write it as markdown in the KB via **`kb-curate`** (ontology: `node_type`,
   frontmatter, typed links `links.documents: [src/…]`). The spec is durable knowledge,
   not a throwaway ticket — searchable, linkable, graphable.
5. **Isolate** — work in a dedicated **`git worktree`**: `main` stays untouched, parallel
   agents don't collide, and rollback is just dropping the worktree.
6. **Implement** — code to the spec inside the worktree; keep doc↔code linked
   (`implemented_by`).
7. **Tests** — write/adjust unit + E2E for the feature. The test is part of the feature,
   not an afterthought.
8. **Independent review** — run an **independent model** (e.g. Codex CLI, read-only) over
   the diff for logic and security bugs before rollout. A second model catches what the
   author's model misses — on a real production codebase this pass caught **191 bugs**
   before they reached prod.
9. **Dev-tests** — open an **MR with the commits into the `dev` branch**; run the full
   suite there. Red → fix in the worktree, don't merge.
10. **Prod-tests** — E2E/smoke against the **real prod contour**, not only mocks or dev.
    Verify behaviour where users live.
11. **Ship** — merge **`dev → main`** and deploy (build the new image *before* stopping the
    old container, then poll the healthcheck to measure real downtime).

## Git-flow

```
git worktree  →  MR + commits  →  dev branch (dev-tests)  →  main (prod-tests + deploy)  →  prod
```

## Principles

- **Spec = markdown + skills.** No ceremony, but ontological — so it stays searchable,
  linkable and graphable (`kb-search` / `gitmark map`).

# kb-curate — how to maintain the knowledge base (GitMark ontology)

Full model: `docs/ontology.md`. This skill is the operational checklist. Principle:
**md+git is the source of truth, with an ontology on top** (object types / properties /
links — inspired by Palantir Foundry/Gotham, compatible with Google's Open Knowledge
Format (OKF) frontmatter).

## Before writing — search, don't duplicate

```bash
python3 <plugin>/skills/kb-search/gitmark.py search "<topic>"
python3 <plugin>/skills/kb-search/gitmark.py query type=<type> --fields path,title   # what exists
```
If the topic already exists — **edit the existing doc**, don't create a second one.

## When ADDING knowledge (CREATE)

1. **Pick a `node_type`**: `service` · `reference` · `runbook` · `gotcha` · `decision`
   · `plan` · `guide` · `report` · `index`. Unsure → spec = `reference`, how-to = `guide`.
2. **Put it in the right folder** (type → folder): service-specific →
   `docs/services/<svc>/`; cross-cutting → `docs/reference/`; ops procedure →
   `docs/ops/`; plan → `docs/plans/`; decision → `docs/decisions/`.
3. **Add frontmatter** (min `node_type`; for load-bearing docs also `title`,
   `description`, `service`, `status: active`, `updated: YYYY-MM-DD`):
   ```yaml
   ---
   node_type: runbook
   title: Deploy the gateway
   description: "How to roll out (deploy) the API gateway to prod and roll back if healthchecks fail."
   service: api
   status: active
   updated: 2026-06-06
   generated: { by: claude-code/<model>, at: 2026-06-06T10:00:00Z }
   links:
     documents: [../../scripts/deploy.sh]
     depends_on: [../reference/architecture.md]
   ---
   ```
   - **`description`** — one sentence, 12–30 words, in the words of someone who has *not*
     read the doc: the task/symptom it answers + key entities, a synonym where natural.
     Not the title again. It is indexed with extra weight and shown in folder indexes.
   - **`generated`** — when an agent wrote or substantially rewrote the content:
     `{ by: <tool>/<model>, at: <ISO datetime>Z }`. A human author: `by: human:<id>`.
   - **`verified`** — *only* the actor who actually checked the content against reality
     adds it: `verified: [{ by: human:<id>, at: … }]` or `process:<name>`. **An agent
     never writes `human:` into `verified` on its own** — that is the whole point of the
     trust tier. Content changed materially → drop stale `verified` entries.
   - **`stale_after`** — for perishable facts (hosts, versions, counts, "current state"):
     an ISO instant after which the doc must be re-checked. `lint` flags it (I8).
4. **Add ≥1 link** — to code (`documents`/`implemented_by`) or a sibling doc
   (`depends_on`/`relates_to`). No orphans. Paths are relative to the doc, or start with
   `/` for repo-root-relative (OKF style, stable when docs move).
5. **Add a line to the folder's `README.md`** (its index): `- [Title](file.md) — description`.

## When EDITING (UPDATE)

- Meaning changed → bump `updated:` (and `generated.at` if an agent rewrote it).
- Doc is stale → `status: deprecated` and set `supersedes: [old.md]` on the replacement.
  Junk → delete (git keeps history).

## When MOVING (reorganizing)

- `git mv` (preserves history), then **rewrite every link** to it and update the
  README indexes of both folders.

## Always at the end

```bash
python3 <plugin>/skills/kb-search/gitmark.py lint     # invariants I1–I8
python3 <plugin>/skills/kb-search/gitmark.py index    # rebuild search
python3 <plugin>/skills/kb-search/gitmark.py health   # optional: KB scorecard
```
`lint` flags: missing/broken frontmatter, values outside vocabularies, orphans, broken
links, folder without README, `supersedes` target still live, typed link to a missing
code path, past `stale_after`. Fix until clean.

## Vocabularies (don't invent values)

- `node_type`: service|reference|runbook|gotcha|decision|plan|guide|report|index
  (OKF's `type:` is accepted as a synonym)
- `status`: active|draft|deprecated|archived (OKF `stable` = active)
- link types: documents|depends_on|supersedes|relates_to|implemented_by|part_of
- `service`: your project's controlled vocabulary. Declare it (and any extra types,
  statuses, link types) in the frontmatter of `docs/ontology.md`:
  ```yaml
  vocab:
    service: [api, billing, frontend]
    node_type: [meeting]
  ```
  Without `vocab.service`, lint derives it from folder names under `docs/` and
  `services|apps|packages/`. Values starting with `_` (`_platform`) are sentinels.

"""GitMark Memory Bank — CLI для базы знаний на чистом md + README + git.

Source of truth = markdown. Всё производное (поисковый индекс, HTML-обзор, граф)
регенерится из md → git остаётся чистым (.gitmark/ в .gitignore).

Поиск: SQLite FTS5 — несколько каналов (bm25 по чанкам, bm25 по title/description/
tags, trigram-подстрока, fuzzy 4-граммы), слитые RRF на уровне
файлов. Frontmatter (тип, статус, trust, stale) — в индексе и в фильтрах.
Чистый python stdlib (PyYAML — опционально, для полного YAML). Оффлайн.

Команды:
    gitmark [--root .] index                  построить индекс
    gitmark search "<q>" [-k 8] [--json] [--type T] [--status S] [--service S]
                   [--scope all|live|history]
    gitmark query  [key=val key!=val key~sub key>val key? !key …] [--fields …]

    gitmark health [--json]                   скоркард БЗ: типизация, связи, trust, stale
    gitmark version

Совместимо с Open Knowledge Format (OKF v0.2): `type` = синоним `node_type`,
`description`, `generated`/`verified` (trust tier), `stale_after`, `status: stable`,

def repo_root(start: Path) -> Path:
    p = start.resolve()
    for cand in [p, *p.parents]:
        if (cand / ".git").exists():
            return cand
    return p


def ignored_prefixes(root: Path) -> tuple:
    """.gitmarkignore в корне: путь на строку (папка или файл от корня), # — комментарий."""
    f = root / IGNORE_FILE
    if not f.exists():
        return ()
    return tuple(l.strip().strip("/") for l in f.read_text(encoding="utf-8").splitlines()
                 if l.strip() and not l.lstrip().startswith("#"))


def _git_md(root: Path) -> list | None:
    """*.md, которые видит git (tracked + untracked, без .gitignore). None — не git-репо."""
    try:
        r = subprocess.run(["git", "-C", str(root), "ls-files", "-co", "--exclude-standard",
                            "-z", "--", "*.md"], capture_output=True, timeout=60)
    except (OSError, subprocess.SubprocessError):
        return None
    if r.returncode != 0:
        return None
    return [x for x in r.stdout.decode("utf-8", "replace").split("\0") if x]


def iter_md(root: Path):
    """Markdown базы знаний. В git-репо — то, что видит git (вендорные/игнорируемые
    папки отпадают сами), иначе обход ФС. Плюс EXCLUDE_DIRS и .gitmarkignore."""
    skip = ignored_prefixes(root)
    rels = _git_md(root)
    if rels is None or os.environ.get("GITMARK_NO_GIT"):
        rels = [p.relative_to(root).as_posix() for p in root.rglob("*.md")]
    for rel in sorted(set(rels)):
        parts = rel.split("/")
        if any(part in EXCLUDE_DIRS for part in parts[:-1]):
            continue
        if any(rel == s or rel.startswith(s + "/") for s in skip):
            continue
        p = root / rel
        if p.is_file():
            yield p


def area_of(rel: str) -> str:
    parts = rel.split("/")
    if parts[0] == "docs":
        # docs/services/<svc> разносим по сервисам (отдельная группа/цвет), прочее — docs/<sub>
        if len(parts) > 3 and parts[1] == "services":
            return "docs/services/" + parts[2]
        return "docs/" + parts[1] if len(parts) > 2 else "docs"
    if parts[0] == "services" and len(parts) > 1:
        return "services/" + parts[1]
    if len(parts) == 1:
        return "(root)"
    return parts[0]


def title_of(text: str, rel: str) -> str:
    m = H1_RE.search(text)
    if m:
        return re.sub(r"[`*]", "", m.group(1)).strip()[:90]
    return Path(rel).name


def chunk_md(text: str, line_offset: int = 0):
    """Чанкуем по заголовкам → (line_start, heading, body). line_offset — строки frontmatter."""
    lines = text.split("\n")
    chunks, cur = [], {"line": 1 + line_offset, "heading": "", "body": []}
    in_fence = False
    for i, ln in enumerate(lines, 1 + line_offset):
        if ln.lstrip().startswith("```"):
            in_fence = not in_fence
        m = None if in_fence else HEAD_RE.match(ln)
        if m:
            if cur["body"] or cur["heading"]:
                chunks.append((cur["line"], cur["heading"], "\n".join(cur["body"])))
            cur = {"line": i, "heading": m.group(2).strip(), "body": [ln]}
        else:
            cur["body"].append(ln)
    if any(x.strip() for x in cur["body"]) or cur["heading"]:
        chunks.append((cur["line"], cur["heading"], "\n".join(cur["body"])))
    return chunks


def _nfc(s: str) -> str:
    return unicodedata.normalize("NFC", s)


def resolve_link(src_rel: str, href: str, known: set) -> str | None:
    """md-ссылка → путь известного дока. `/x.md` — от корня (OKF), иначе от папки src."""
    import posixpath
    href = _nfc(href.split("#")[0].strip().strip("<>"))
    if not href or not href.endswith(".md") or href.startswith(("http", "mailto:")):
        return None
    src_dir = Path(_nfc(src_rel)).parent
    if href.startswith("/"):
        cands = [href.lstrip("/")]
    else:
        cands = [posixpath.normpath((src_dir / href).as_posix()), href.lstrip("./")]
    for c in cands:
        if c in known:
            return c
    base = Path(href).name
    hits = [r for r in known if r.endswith("/" + base) or r == base]
    return hits[0] if len(hits) == 1 else None

def split_frontmatter(text: str):
    """→ (yaml-текст | None, тело, число строк, занятых frontmatter)."""
    m = FM_RE.match(text)
    if not m:
        return None, text.lstrip("﻿"), 0
    return m.group(1), text[m.end():], m.group(0).count("\n")


def _plain(v):
    """PyYAML-значения → JSON-совместимые (даты → ISO-строки)."""
    if isinstance(v, dict):
        return {str(k): _plain(x) for k, x in v.items()}
    if isinstance(v, (list, tuple)):
        return [_plain(x) for x in v]
    if isinstance(v, (_dt.date, _dt.datetime)):
        return v.isoformat().replace("+00:00", "Z")
    return v


def _strip_comment(line: str) -> str:
    """Убрать YAML-комментарий ` # …` вне кавычек."""
    q = None
    for i, ch in enumerate(line):
        if q:
            if ch == q:
                q = None
        elif ch in "'\"":
            q = ch
        elif ch == "#" and (i == 0 or line[i - 1] in " \t"):
            return line[:i]
    return line


def _split_top(s: str) -> list:
    """Разбить по запятым верхнего уровня (не внутри [] {} и кавычек)."""
    out, depth, q, cur = [], 0, None, ""
    for ch in s:
        if q:
            q = None if ch == q else q
        elif ch in "'\"":
            q = ch
        elif ch in "[{":
            depth += 1
        elif ch in "]}":
            depth -= 1
        elif ch == "," and depth == 0:
            out.append(cur)
            cur = ""
            continue
        cur += ch
    if cur.strip():
        out.append(cur)
    return [x.strip() for x in out]


_KV_RE = re.compile(r"^([^\s'\"\[{#-][^:]*?|\"[^\"]*\"|'[^']*'):(?:\s+(.*)|\s*)$")


def _scalar(v: str):
    v = v.strip()
    if not v:
        return None
    if v[0] == "[" and v[-1] == "]":
        return [_scalar(x) for x in _split_top(v[1:-1])]
    if v[0] == "{" and v[-1] == "}":
        d = {}
        for part in _split_top(v[1:-1]):
            m = _KV_RE.match(part)
            if m:
                d[m.group(1).strip("'\"")] = _scalar(m.group(2) or "")
        return d
    if len(v) > 1 and v[0] == v[-1] and v[0] in "'\"":
        return v[1:-1]
    low = v.lower()
    if low in ("true", "false"):
        return low == "true"
    if low in ("null", "~"):
        return None
    if re.fullmatch(r"-?\d+", v):
        return int(v)
    return v


def _mini_yaml(raw: str) -> dict:
    """Мини-парсер YAML (stdlib): скаляры, flow [..]/{..}, вложенные map/list по отступам,
    блочные скаляры | и >, комментарии. Покрывает то, что реально пишут во frontmatter."""
    root: dict = {}
    stack = [(-1, root)]          # (мин. отступ элементов, контейнер)
    pending = None                # (отступ, dict, ключ) — ключ без значения ждёт блок
    block = None                  # (отступ ключа, dict, ключ, style, [строки]) — | или >
    for line in raw.split("\n"):
        if block:
            ind = len(line) - len(line.lstrip(" \t"))
            if not line.strip() or ind > block[0]:
                block[4].append(line.strip())
                continue
            sep = "\n" if block[3] == "|" else " "
            block[1][block[2]] = sep.join(block[4]).strip()
            block = None
        line = _strip_comment(line).rstrip()
        if not line.strip():
            continue
        ind = len(line) - len(line.lstrip(" \t"))
        s = line.strip()
        is_item = s == "-" or s.startswith("- ")
        if pending:
            pind, pd, pkey = pending
            pending = None
            if ind > pind or (is_item and ind == pind):
                cont = [] if is_item else {}
                pd[pkey] = cont
                stack.append((ind, cont))
        while len(stack) > 1:
            mind, cont = stack[-1]
            if ind < mind or (ind == mind and isinstance(cont, list) != is_item):
                stack.pop()
            else:
                break
        cont = stack[-1][1]
        if is_item and isinstance(cont, list):
            val = s[1:].strip()
            m = _KV_RE.match(val) if val and val[0] not in "[{'\"" else None
            if m:                                     # "- key: v" — map внутри списка
                d = {}
                cont.append(d)
                stack.append((ind + 2, d))
                k, v = m.group(1).strip("'\""), m.group(2) or ""
                d[k] = _scalar(v) if v else None
                if not v:
                    pending = (ind + 2, d, k)
            else:
                cont.append(_scalar(val))
            continue
        if not isinstance(cont, dict):
            continue
        m = _KV_RE.match(s)
        if not m:
            continue
        k, v = m.group(1).strip("'\""), (m.group(2) or "").strip()
        if v in ("|", ">", "|-", ">-", "|+", ">+"):
            block = (ind, cont, k, v[0], [])
            cont[k] = ""
        elif not v:
            cont[k] = None
            pending = (ind, cont, k)
        else:
            cont[k] = _scalar(v)
    if block:
        block[1][block[2]] = ("\n" if block[3] == "|" else " ").join(block[4]).strip()
    return root


def parse_frontmatter(text: str) -> dict | None:
    """YAML-frontmatter → dict (None — нет frontmatter). PyYAML если есть, иначе мини-парсер;
    мини-парсер же — фолбэк на «почти-YAML», который PyYAML не принимает (`title: a: b`)."""
    raw, _, _ = split_frontmatter(text)
    if raw is None:
        return None
    y = _load_yaml()
    if y is not None:
        try:
            data = y.safe_load(raw)
            if isinstance(data, dict):
                return _plain(data)
        except Exception:
            pass
    return _mini_yaml(raw)


def as_list(v) -> list:
    if v is None or v == "":
        return []
    if isinstance(v, list):
        return [x for x in v if x is not None and x != ""]
    return [v]


def trust_tier(fm: dict) -> str:
    """OKF §5.3: нет verified → unverified; только машины → machine; есть human: → human."""
    ver = (fm or {}).get("verified")
    if not ver:
        return "unverified"
    evs = ver if isinstance(ver, list) else [ver]
    bys = [str(e.get("by", "")) if isinstance(e, dict) else str(e) for e in evs]
    return "human" if any(b.startswith("human:") for b in bys) else "machine"


def _parse_when(v) -> _dt.datetime | None:
    if not v:
        return None
    s = str(v).strip().replace("Z", "+00:00")
    try:
        d = _dt.datetime.fromisoformat(s)
    except ValueError:
        try:
            d = _dt.datetime.fromisoformat(s[:10])
        except ValueError:
            return None
    return d if d.tzinfo else d.replace(tzinfo=_dt.timezone.utc)


def is_stale(fm: dict, now: _dt.datetime | None = None) -> bool:
    """OKF §5.5: stale, когда now >= stale_after."""
    when = _parse_when((fm or {}).get("stale_after"))
    return bool(when and (now or _dt.datetime.now(_dt.timezone.utc)) >= when)


def node_type_of(fm: dict | None) -> str | None:
    """`node_type` (OntoShip) или `type` (OKF)."""
    fm = fm or {}
    nt = fm.get("node_type") or fm.get("type")
    return str(nt).strip() if nt else None


def fm_links(fm: dict | None) -> list:
    """Типизированные связи из `links:` → [(link_type, target), …]."""
    links = (fm or {}).get("links")
    if not isinstance(links, dict):
        return []
    return [(str(lt), str(t).strip()) for lt, ts in links.items()
            for t in as_list(ts) if str(t).strip()]


def load_doc(root: Path, p: Path) -> dict | None:
    """Прочитать md → {rel, text, body, offset, fm, meta}. None — не читается."""
    rel = p.relative_to(root).as_posix()
    try:
        text = p.read_text(encoding="utf-8", errors="replace").replace("\r\n", "\n")
    except OSError:
        return None
    _, body, offset = split_frontmatter(text)
    fm = parse_frontmatter(text) or {}
    gen = fm.get("generated") if isinstance(fm.get("generated"), dict) else {}
    meta = {
        "node_type": node_type_of(fm) or "",
        "title": str(fm.get("title") or title_of(body, rel)),
        "description": str(fm.get("description") or ""),
        "tags": [str(x) for x in as_list(fm.get("tags"))],
        "aliases": [str(x) for x in as_list(fm.get("aliases"))],
        "status": str(fm.get("status") or ""),
        "service": [x.strip() for v in as_list(fm.get("service")) for x in str(v).split(",") if x.strip()],
        "updated": str(fm.get("updated") or gen.get("at") or ""),   # OKF: generated.at
        "trust": trust_tier(fm),
        "stale": is_stale(fm),
    }
    return {"rel": rel, "text": text, "body": body, "offset": offset,
            "fm": fm if text.startswith(("---", "﻿---")) else None, "meta": meta}


def load_docs(root: Path) -> dict:
    out = {}
    for p in iter_md(root):
        d = load_doc(root, p)
        if d:
            out[_nfc(d["rel"])] = d
    return out


def doc_edges(d: dict, known: set) -> list:
    """Все связи дока: (dst, link_type, kind). kind: doc|code|url|missing."""
    rel, out, seen = d["rel"], [], set()
    for lt, t in fm_links(d["fm"]):
        dst = resolve_link(rel, t, known)
        if dst:
            kind = "doc"
        elif t.startswith(("http://", "https://")):
            dst, kind = t, "url"
        else:
            dst, kind = t, "code"
        if (dst, lt) not in seen:
            seen.add((dst, lt))
            out.append((dst, lt, kind))
    for href in LINK_RE.findall(strip_code(d["body"])):
        dst = resolve_link(rel, href.split()[0] if href.split() else href, known)
        if dst and dst != rel and not any(o[0] == dst for o in out):
            out.append((dst, "relates_to", "doc"))
    return out

def _has_trigram(con) -> bool:
    try:
        con.execute("CREATE VIRTUAL TABLE _tri_probe USING fts5(x, tokenize='trigram')")
        con.execute("DROP TABLE _tri_probe")
        return True
    except sqlite3.OperationalError:
        return False


def cmd_index(root: Path, force: bool = False) -> dict:
    """Индекс — кэш: всегда пересобирается целиком (быстро; схема меняется между версиями)."""
    db = root / DB_REL
    db.parent.mkdir(parents=True, exist_ok=True)
    if db.exists():
        db.unlink()
    con = sqlite3.connect(db)
    tok = "tokenize='unicode61 remove_diacritics 2'"
    try:
        con.execute(f"CREATE VIRTUAL TABLE fts USING fts5(path UNINDEXED, lineno UNINDEXED, heading, body, {tok})")
        con.execute(f"CREATE VIRTUAL TABLE dfts USING fts5(path UNINDEXED, title, meta, {tok})")
    except sqlite3.OperationalError as e:
        print(f"ОШИБКА: SQLite без FTS5 ({e}). Нужен python с FTS5.", file=sys.stderr)
        sys.exit(2)
    has_tri = _has_trigram(con)
    if has_tri:
        con.execute("CREATE VIRTUAL TABLE tri USING fts5(path UNINDEXED, lineno UNINDEXED, body, tokenize='trigram')")
    con.execute("CREATE TABLE files(path TEXT PRIMARY KEY, title TEXT, area TEXT, size INT, chunks INT, "
                "node_type TEXT, status TEXT, service TEXT, description TEXT, updated TEXT, "
                "trust TEXT, stale INT, fm TEXT)")
    con.execute("CREATE TABLE links(src TEXT, dst TEXT, type TEXT, kind TEXT)")
    con.execute("CREATE TABLE meta(k TEXT PRIMARY KEY, v TEXT)")

    docs = load_docs(root)
    known = set(docs)
    nchunks = 0
    for rel, d in docs.items():
        m = d["meta"]
        chs = chunk_md(d["body"], d["offset"])
        for line, heading, body in chs:
            con.execute("INSERT INTO fts VALUES(?,?,?,?)", (rel, str(line), heading, body))
            if has_tri:
                con.execute("INSERT INTO tri VALUES(?,?,?)", (rel, str(line), heading + "\n" + body))
        nchunks += len(chs)
        path_words = " ".join(re.split(r"[/_.\-]+", rel.rsplit(".", 1)[0]))
        con.execute("INSERT INTO dfts VALUES(?,?,?)", (
            rel, m["title"],
            " ".join([m["description"], " ".join(m["tags"]), " ".join(m["aliases"]), path_words])))
        con.execute("INSERT INTO files VALUES(?,?,?,?,?,?,?,?,?,?,?,?,?)", (
            rel, m["title"], area_of(rel), len(d["text"].encode("utf-8")), len(chs),
            m["node_type"], m["status"], ",".join(m["service"]), m["description"], m["updated"],
            m["trust"], int(m["stale"]), json.dumps(d["fm"], ensure_ascii=False, default=str)))
        for dst, lt, kind in doc_edges(d, known):
            con.execute("INSERT INTO links VALUES(?,?,?,?)", (rel, dst, lt, kind))
    con.execute("INSERT OR REPLACE INTO meta VALUES('trigram', ?)", ("1" if has_tri else "0",))
    con.execute("INSERT OR REPLACE INTO meta VALUES('version', ?)", (VERSION,))
    con.commit()
    n_links = con.execute("SELECT count(*) FROM links WHERE kind='doc'").fetchone()[0]
    con.close()
    return {"files": len(docs), "chunks": nchunks, "links": n_links,
            "trigram": has_tri, "db": str(db.relative_to(root))}

_CYR = re.compile(r"[а-яё]")


def stem(w: str) -> str:
    """Лёгкий стеммер ru/en: срезать одно окончание, оставив основу ≥4 символов.
    Запрос ищется префиксом основы — «деплоймента» найдёт «деплоймент», «деплойменты»."""
    if len(w) <= 4:
        return w
    for e in (_RU_END if _CYR.search(w) else _EN_END):
        if w.endswith(e) and len(w) - len(e) >= 4:
            return w[:-len(e)]
    return w


def query_terms(query: str) -> list:
    """Значимые термины запроса (lower, без стоп-слов; если всё стоп-слова — оставить всё)."""
    words = [w.lower().strip("-") for w in WORD_RE.findall(query)]
    words = [w for w in words if len(w) >= 2]
    sig = [w for w in words if w not in STOPWORDS]
    out, seen = [], set()
    for w in sig or words:
        if w not in seen:
            seen.add(w)
            out.append(w)
    return out


def _fts_match_query(query: str) -> str:
    return " OR ".join(f'"{stem(t)}"*' for t in query_terms(query))


def _fuzzy_phrases(s: str) -> list:
    """Фразы из пар соседних 3-грамм = 4-символьные подстроки запроса.

    Матч по 4-символьным окнам (а не одиночным 3-граммам) отсекает мусор: опечатка
    сохраняет длинные общие подстроки (`firecraker`↔`firecracker`: `fire`,`ecra`),
    а случайная строка делит с доками лишь разрозненные частые 3-граммы (`ent`,`non`).
    """
    wins, seen = [], set()
    for w in query_terms(s):
        if len(w) < 4:
            continue
        for i in range(len(w) - 3):
            win = w[i:i + 4]            # 4-символьное окно; FTS5-trigram сам разложит
            if '"' in win or win in seen:
                continue
            seen.add(win)
            wins.append(win)
    return wins


# Веса каналов в RRF и константа сглаживания. Подобраны на bench/ (см. bench/README.md).
CHANNEL_W = {"chunk": 1.0, "doc": 0.5, "phrase": 0.6, "fuzzy": 0.5}
RRF_K = 5
PRIOR = {"typed": 1.3, "index": 0.7, "retired": 0.6, "stale": 0.85}
HUB_NAMES = {"changelog.md", "log.md", "history.md"}
# Исторические типы — датированные снимки (замысел до реализации, разовый аудит), которые
# расходятся с фактом. `--scope live` их прячет, `--scope history` ищет только по ним.
HISTORICAL_TYPES = {"plan", "report"}     # хроники упоминают всё подряд
if os.environ.get("GITMARK_TUNE"):                        # для bench/: подбор весов без правки кода
    _t = json.loads(os.environ["GITMARK_TUNE"])
    CHANNEL_W.update(_t.get("CHANNEL_W", {}))
    PRIOR.update(_t.get("PRIOR", {}))
    RRF_K = _t.get("RRF_K", RRF_K)


def _allowed(con, types=None, statuses=None, services=None, scope="all") -> set | None:
    if not (types or statuses or services) and scope == "all":
        return None
    ok = set()
    for path, nt, st, svc in con.execute("SELECT path,node_type,status,service FROM files"):
        if types and nt not in types:
            continue
        if scope == "live" and nt in HISTORICAL_TYPES or scope == "history" and nt not in HISTORICAL_TYPES:
            continue
        if statuses and st not in statuses:
            continue
        if services and not set(svc.split(",")) & set(services):
            continue
        ok.add(path)
    return ok


def cmd_search(root: Path, query: str, k: int = 8, types=None, statuses=None,
               services=None, scope: str = "all") -> list:
    """Поиск: каналы → ранги файлов → RRF → приоры (типизирован / index / deprecated / stale).
    Один результат на файл — лучший чанк (path:line + сниппет)."""
    db = root / DB_REL
    if not db.exists():
        raise SystemExit("Индекс не найден — запусти `gitmark index`")
    con = sqlite3.connect(db)
    try:
        con.execute("SELECT trust FROM files LIMIT 1")
    except sqlite3.OperationalError:
        raise SystemExit("Индекс старой версии — запусти `gitmark index`")
    has_tri = (con.execute("SELECT v FROM meta WHERE k='trigram'").fetchone() or ("0",))[0] == "1"
    allowed = _allowed(con, types, statuses, services, scope)
    ranks: dict = defaultdict(dict)        # channel → {path: rank}
    best: dict = {}                        # path → лучший чанк {line, heading, snippet}
    N = max(60, k * 8)

    def take(channel, rows, with_chunk=True):
        r = 0
        for row in rows:
            path = row[0]
            if allowed is not None and path not in allowed:
                continue
            if path in ranks[channel]:
                continue
            r += 1
            ranks[channel][path] = r
            if with_chunk and path not in best:
                best[path] = {"line": int(row[1]), "heading": row[2], "snippet": " ".join(row[3].split())}

    bm_q = _fts_match_query(query)
    if bm_q:
        try:   # (1) bm25 по чанкам; заголовок весит больше тела
            take("chunk", con.execute(
                "SELECT path,lineno,heading,snippet(fts,3,'»','«','…',14) FROM fts "
                "WHERE fts MATCH ? ORDER BY bm25(fts,0,0,2.0,1.0) LIMIT ?", (bm_q, N)))
        except sqlite3.OperationalError:
            pass
        try:   # (2) bm25 по документу: title, description/tags/aliases/путь
            take("doc", con.execute(
                "SELECT path FROM dfts WHERE dfts MATCH ? ORDER BY bm25(dfts,0,3.0,1.5) LIMIT ?",
                (bm_q, N)), with_chunk=False)
        except sqlite3.OperationalError:
            pass
    if has_tri and len(query.strip()) >= 3:
        try:   # (3) точная подстрока
            tq = '"' + query.replace('"', " ").strip() + '"'
            take("phrase", con.execute(
                "SELECT path,lineno,'',snippet(tri,2,'»','«','…',14) FROM tri "
                "WHERE tri MATCH ? ORDER BY bm25(tri) LIMIT ?", (tq, N)))
        except sqlite3.OperationalError:
            pass
        # (4) fuzzy: OR по 4-символьным окнам → опечатки/морфология/кириллица.
        # Порог покрытия: чанк принимается, только если содержит ≥ ceil(20%) окон запроса.
        grams = _fuzzy_phrases(query)
        if grams:
            need = max(1, (len(grams) + 4) // 5)
            fq = " OR ".join(f'"{g}"' for g in grams)
            try:
                rows = []
                for path, lineno, snip, body in con.execute(
                        "SELECT path,lineno,snippet(tri,2,'»','«','…',14),body FROM tri "
                        "WHERE tri MATCH ? ORDER BY bm25(tri) LIMIT ?", (fq, N * 2)):
                    bl = body.lower()
                    if sum(1 for g in grams if g in bl) >= need:
                        rows.append((path, lineno, "", snip))
                take("fuzzy", rows)
            except sqlite3.OperationalError:
                pass

    fused: dict = defaultdict(float)
    via: dict = defaultdict(list)
    for ch, rk in ranks.items():
        for path, r in rk.items():
            fused[path] += CHANNEL_W[ch] / (RRF_K + r)
            via[path].append(ch)
    if not fused:
        con.close()
        return []
    info = {r[0]: r[1:] for r in con.execute(
        "SELECT path,title,node_type,status,trust,stale FROM files WHERE path IN (%s)"
        % ",".join("?" * len(fused)), tuple(fused))}
    for path in fused:
        title, nt, st, trust, stale = info.get(path, ("", "", "", "", 0))
        f = PRIOR["typed"] if nt else 1.0
        if nt == "index" or Path(path).name.lower() in HUB_NAMES:
            f *= PRIOR["index"]
        if st in ("deprecated", "archived", "superseded"):
            f *= PRIOR["retired"]
        if stale:
            f *= PRIOR["stale"]
        fused[path] *= f
    top = sorted(fused, key=lambda p: -fused[p])[:k]
    out = []
    for path in top:
        title, nt, st, trust, stale = info.get(path, ("", "", "", "", 0))
        b = best.get(path)
        if b is None:                       # файл найден только по doc-каналу — берём первый чанк
            row = con.execute("SELECT lineno,heading,substr(body,1,240) FROM fts WHERE path=? "
                              "ORDER BY CAST(lineno AS INT) LIMIT 1", (path,)).fetchone() or (1, "", "")
            b = {"line": int(row[0]), "heading": row[1], "snippet": " ".join(row[2].split())}
        out.append({"path": path, "line": b["line"], "heading": b["heading"],
                    "snippet": b["snippet"], "score": round(fused[path], 5),
                    "via": "+".join(via[path]), "title": title, "node_type": nt,
                    "status": st, "trust": trust, "stale": bool(stale)})
    con.close()
    return out


# ─────────────────────────── query (структурные вопросы к frontmatter) ───────────────────────────
_COND_RE = re.compile(r"^(!)?([\w.\-]+)(?:(!=|>=|<=|=|~|>|<)(.*)|(\?))?$")


def _get_path(fm: dict, key: str) -> list:
    """`a.b` по frontmatter → плоский список значений (сквозь списки)."""
    vals = [fm]
    for part in key.split("."):
        nxt = []
        for v in vals:
            if isinstance(v, list):
                v_items = v
            else:
                v_items = [v]
            for it in v_items:
                if isinstance(it, dict) and part in it:
                    x = it[part]
                    nxt.extend(x if isinstance(x, list) else [x])
        vals = nxt
    return [v for v in vals if v is not None and v != ""]


def doc_record(d: dict) -> dict:
    """frontmatter + вычисляемые поля: path, area, type, trust, stale, links.<type>."""
    rec = dict(d["fm"] or {})
    m = d["meta"]
    rec.update({"path": d["rel"], "area": area_of(d["rel"]), "type": m["node_type"],
                "node_type": m["node_type"], "title": m["title"], "trust": m["trust"],
                "stale": m["stale"]})
    return rec


def match_cond(rec: dict, cond: str) -> bool:
    m = _COND_RE.match(cond.strip())
    if not m:
        raise SystemExit(f"не понял условие: {cond!r} (ожидаю key=val, key!=val, key~sub, "
                         f"key>val, key<val, key?, !key)")
    neg, key, op, val, exists = m.groups()
    vals = [str(v).lower() if not isinstance(v, bool) else str(v).lower()
            for v in _get_path(rec, key)]
    if neg and not op:
        return not vals
    if exists or not op:
        return bool(vals)
    val = (val or "").strip().strip("'\"").lower()
    alts = [x.strip() for x in val.split("|")]
    if op == "=":
        return any(v in alts for v in vals)
    if op == "!=":
        return not any(v in alts for v in vals)
    if op == "~":
        return any(a in v for v in vals for a in alts)
    cmp = {">": lambda a, b: a > b, "<": lambda a, b: a < b,
           ">=": lambda a, b: a >= b, "<=": lambda a, b: a <= b}[op]
    return any(cmp(v, val) for v in vals)


def cmd_query(root: Path, conds: list, count_by: str | None = None) -> dict:
    """Фильтр по frontmatter прямо из md (источник истины), без индекса."""
    rows = [doc_record(d) for d in load_docs(root).values() if d["fm"] is not None]
    hits = [r for r in rows if all(match_cond(r, c) for c in conds)]
    res = {"total": len(rows), "matched": len(hits), "rows": hits}
    if count_by:
        cnt = Counter()
        for r in hits:
            for v in _get_path(r, count_by) or ["(нет)"]:
                cnt[str(v)] += 1
        res["counts"] = cnt.most_common()
    return res


# ─────────────────────────── stat ───────────────────────────
def cmd_stat(root: Path) -> dict:
    db = root / DB_REL
    if not db.exists():
        return {"indexed": False}
    con = sqlite3.connect(db)
    try:
        f = con.execute("SELECT count(*), coalesce(sum(size),0), coalesce(sum(chunks),0) FROM files").fetchone()
        links = con.execute("SELECT count(*) FROM links WHERE kind='doc'").fetchone()[0]
        typed = con.execute("SELECT count(*) FROM links WHERE type!='relates_to'").fetchone()[0]
        areas = con.execute("SELECT count(DISTINCT area) FROM files").fetchone()[0]
        types = con.execute("SELECT node_type, count(*) FROM files WHERE node_type!='' "
                            "GROUP BY 1 ORDER BY 2 DESC").fetchall()
    except sqlite3.OperationalError:
        con.close()
        return {"indexed": False, "stale_schema": True}
    has_tri = (con.execute("SELECT v FROM meta WHERE k='trigram'").fetchone() or ("0",))[0] == "1"
    con.close()
    return {"indexed": True, "files": f[0], "bytes": f[1], "chunks": f[2], "links": links,
            "typed_links": typed, "areas": areas, "trigram": has_tri, "types": types}


# ─────────────────────────── lint (онтология) ───────────────────────────
# Словари по умолчанию. Проект расширяет их в frontmatter своего ontology.md:
#   vocab: { node_type: [meeting], service: [api, billing], status: [done] }
NODE_TYPES = {"service", "reference", "runbook", "gotcha", "decision",
              "plan", "guide", "report", "index", "memory"}
# Реальный словарь сервисов выводится per-repo из имён папок docs/** + vocab.service.
SERVICES = {"_platform"}
STATUSES = {"active", "draft", "deprecated", "archived", "stable"}   # stable — OKF
LOAD_BEARING = {"service", "reference", "runbook", "plan", "decision"}
BEARING_DIRS = {"reference", "ops", "plans", "decisions", "services"}
CODE_DIRS = ("services", "apps", "packages", "libs", "modules")
LINK_KEYS = {"documents", "depends_on", "supersedes", "relates_to",
             "implemented_by", "part_of"}
FENCE_RE = re.compile(r"```.*?```", re.DOTALL)
INLINE_CODE_RE = re.compile(r"`[^`]*`")

INVARIANTS = {
    "I1": "несущий документ без frontmatter с node_type/type",
    "I2": "значение вне словаря (node_type/service/status/тип связи)",
    "I3": "сирота — нет связей",
    "I4": "битая md-ссылка",
    "I5": "папка docs/ без README.md",
    "I6": "supersedes-цель не deprecated/archived",
    "I7": "links: documents/implemented_by → путь не существует",
    "I8": "просрочен stale_after",
}


def strip_code(text: str) -> str:
    """Убрать fenced ``` и inline `code` — чтобы не ловить ссылки-примеры из кода."""
    return INLINE_CODE_RE.sub(" ", FENCE_RE.sub(" ", text))


def in_kb(rel: str) -> bool:
    """Что линтуется: docs/** и md в корне (README/CLAUDE/AGENTS). Прочие md (код, фикстуры) —
    ищутся, но онтологией не считаются."""
    return rel.startswith("docs/") or "/" not in rel


def project_vocab(docs: dict) -> dict:
    """vocab: из frontmatter любого ontology.md."""
    voc = defaultdict(set)
    for rel, d in docs.items():
        if Path(rel).name != "ontology.md":
            continue
        v = (d["fm"] or {}).get("vocab")
        if isinstance(v, dict):
            for key, vals in v.items():
                voc[key] |= {str(x) for x in as_list(vals)}
    return voc


def _code_path_exists(root: Path, src_rel: str, target: str) -> bool:
    t = target.split("#")[0].strip()
    if not t or "://" in t:
        return True
    base = root if t.startswith("/") else (root / src_rel).parent
    return (base / t.lstrip("/")).exists() or (root / t.lstrip("/")).exists()


def cmd_lint(root: Path, paths: list | None = None) -> dict:
    """Проверка инвариантов онтологии I1–I8. Возвращает {issues, errors, warnings, checked}."""
    docs = load_docs(root)
    known = set(docs)
    voc = project_vocab(docs)
    node_types = NODE_TYPES | voc["node_type"]
    statuses = STATUSES | voc["status"]
    link_keys = LINK_KEYS | voc["link"]
    if voc["service"]:                       # словарь задан явно — он и есть закон
        services_vocab = set(SERVICES) | voc["service"]
    else:                                    # иначе — из папок docs/** и кода services|apps|packages/*
        services_vocab = set(SERVICES)
        docs_root = root / "docs"
        if docs_root.exists():
            services_vocab |= {d.name for d in docs_root.rglob("*") if d.is_dir()}
        for top in CODE_DIRS:
            if (root / top).is_dir():
                services_vocab |= {d.name for d in (root / top).iterdir() if d.is_dir()}
    out_links, in_links, issues = {}, defaultdict(set), []
    sel = set(paths) if paths else None
    edges = {}

    for rel, d in docs.items():
        edges[rel] = doc_edges(d, known)
        outs = set()
        for dst, lt, kind in edges[rel]:
            if kind == "doc":
                outs.add(dst)
                in_links[dst].add(rel)
        out_links[rel] = outs
        if not in_kb(rel):
            continue
        for href in LINK_RE.findall(strip_code(d["body"])):
            h = href.split()[0] if href.split() else href
            if (h.split("#")[0].endswith(".md") and not h.startswith(("http", "mailto:"))
                    and not resolve_link(rel, h, known) and not _code_path_exists(root, rel, h)):
                issues.append(("ERR", "I4", rel, f"битая ссылка → {h}"))

    # README на каждую docs/-папку (I5)
    docs_dirs = {(root / rel).parent for rel in docs if rel.startswith("docs/")}
    for dd in sorted(docs_dirs):
        if not (dd / "README.md").exists() and not (dd / "index.md").exists():
            issues.append(("WARN", "I5", dd.relative_to(root).as_posix() + "/", "нет README.md (индекс папки)"))

    for rel, d in docs.items():
        if sel and rel not in sel:
            continue
        if not rel.startswith("docs/"):
            continue
        fm, nt = d["fm"], d["meta"]["node_type"]
        # I1 — несущий документ без frontmatter/типа
        parts = set(rel.split("/")[1:-1])
        if not fm or not nt:
            if parts & BEARING_DIRS and Path(rel).name not in ("README.md", "index.md", "log.md"):
                issues.append(("ERR", "I1", rel, "нет frontmatter с node_type"))
            continue
        # I2 — значения в словарях
        if nt not in node_types:
            issues.append(("ERR", "I2", rel, f"node_type='{nt}' вне словаря"))
        for svc in d["meta"]["service"]:
            if svc not in services_vocab and not svc.startswith("_"):
                issues.append(("WARN", "I2", rel, f"service='{svc}' вне словаря"))
        st = d["meta"]["status"]
        if st and st not in statuses:
            issues.append(("WARN", "I2", rel, f"status='{st}' вне словаря"))
        for lt, t in fm_links(fm):
            if lt not in link_keys:
                issues.append(("WARN", "I2", rel, f"тип связи '{lt}' вне словаря"))
        # I3 — сироты (несущий тип без входящих/исходящих связей, в т.ч. на код)
        if nt in LOAD_BEARING and not out_links.get(rel) and not in_links.get(rel) and not fm_links(fm):
            issues.append(("WARN", "I3", rel, "сирота — нет связей (ни in, ни out)"))
        for dst, lt, kind in edges[rel]:
            # I6 — supersedes-цель должна быть deprecated/archived
            if lt == "supersedes" and kind == "doc":
                if docs[dst]["meta"]["status"] not in ("deprecated", "archived"):
                    issues.append(("WARN", "I6", rel, f"supersedes {dst}, но он не deprecated/archived"))
            # I4/I7 — цели типизированных связей
            if kind == "code" and dst.endswith(".md") and not _code_path_exists(root, rel, dst):
                issues.append(("ERR", "I4", rel, f"links.{lt} → {dst} — нет такого дока"))
            elif kind == "code" and not _code_path_exists(root, rel, dst):
                issues.append(("WARN", "I7", rel, f"links.{lt} → {dst} — путь не существует"))
        # I8 — просрочен
        if d["meta"]["stale"]:
            issues.append(("WARN", "I8", rel, f"stale_after={fm.get('stale_after')} прошёл — перепроверь"))

    errs = [i for i in issues if i[0] == "ERR"]
    warns = [i for i in issues if i[0] == "WARN"]
    return {"issues": issues, "errors": errs, "warnings": warns, "checked": len(docs)}


# ─────────────────────────── health (скоркард) ───────────────────────────
def cmd_health(root: Path) -> dict:
    """Насколько БЗ — онтология, а не куча файлов. Считается по docs/** (или по всем,
    если docs/ нет): доля с типом/title/description/updated, типизированные связи,
    сироты, битые ссылки, trust-tier, stale, дубли по содержимому."""
    docs = load_docs(root)
    known = set(docs)
    scope = {r: d for r, d in docs.items() if r.startswith("docs/")} or docs
    content = {r: d for r, d in scope.items()
               if Path(r).name not in ("README.md", "index.md", "log.md")}
    n = len(content) or 1
    typed = [d for d in content.values() if d["meta"]["node_type"]]
    fm_of = lambda d: d["fm"] or {}
    linked_in = defaultdict(int)
    edges = {}
    for r, d in docs.items():
        edges[r] = doc_edges(d, known)
        for dst, _, kind in edges[r]:
            if kind == "doc":
                linked_in[dst] += 1
    orphans = [r for r in content if not edges[r] and not linked_in[r]]
    broken = sum(1 for r, d in scope.items() for h in LINK_RE.findall(strip_code(d["body"]))
                 if h.split("#")[0].endswith(".md") and not h.startswith("http")
                 and not resolve_link(r, h.split()[0], known)
                 and not _code_path_exists(root, r, h.split()[0]))
    hashes = defaultdict(list)
    for r, d in docs.items():
        body = re.sub(r"\s+", " ", d["body"]).strip()
        if len(body) > 200:
            hashes[hashlib.sha1(body.encode()).hexdigest()].append(r)
    dups = [v for v in hashes.values() if len(v) > 1]
    trust = Counter(d["meta"]["trust"] for d in content.values())
    pct = lambda c: round(100 * c / n)
    res = {
        "docs": len(content), "indexes": len(scope) - len(content), "all_md": len(docs),
        "typed_pct": pct(len(typed)),
        "title_pct": pct(sum(1 for d in content.values() if fm_of(d).get("title"))),
        "description_pct": pct(sum(1 for d in content.values() if fm_of(d).get("description"))),
        "updated_pct": pct(sum(1 for d in content.values()
                               if fm_of(d).get("updated") or isinstance(fm_of(d).get("generated"), dict))),
        "typed_links_pct": pct(sum(1 for d in content.values() if fm_links(d["fm"]))),
        "code_links_pct": pct(sum(1 for r in content
                                  if any(k == "code" for _, _, k in edges[r]))),
        "orphans": len(orphans), "broken_links": broken,
        "stale": sum(1 for d in content.values() if d["meta"]["stale"]),
        "trust": dict(trust), "duplicate_groups": len(dups),
        "duplicates": dups[:10],
        "types": Counter(d["meta"]["node_type"] for d in typed).most_common(),
    }
    # интегральный балл 0–100: структура (тип/title/updated), связность, гигиена
    score = (0.30 * res["typed_pct"] + 0.10 * res["title_pct"] + 0.10 * res["description_pct"]
             + 0.10 * res["updated_pct"] + 0.15 * res["typed_links_pct"]
             + 0.15 * (100 - pct(len(orphans))) + 0.10 * (100 if broken == 0 else max(0, 100 - 5 * broken)))
    res["score"] = round(score)
    return res


# ─────────────────────────── map (HTML обзор + граф) ───────────────────────────
def cmd_map(root: Path, out: Path) -> dict:
    """Self-contained HTML: дерево + рендер md + радиальный граф от точки входа."""
    try:
        import markdown as _md
        render = lambda t: _md.markdown(t, extensions=["extra", "sane_lists", "tables", "toc"], output_format="html5")
        pretty = True
    except Exception:
        import html as _html
        render = lambda t: f"<pre>{_html.escape(t)}</pre>"
        pretty = False

    docs = load_docs(root)
    known = set(docs)
    files, edges = {}, []
    for rel, d in docs.items():
        files[rel] = {"rel": rel, "area": area_of(rel), "title": d["meta"]["title"],
                      "size": len(d["text"].encode("utf-8")), "html": render(d["body"]),
                      "type": d["meta"]["node_type"], "status": d["meta"]["status"]}
    for rel, d in docs.items():
        for dst, lt, kind in doc_edges(d, known):
            if kind == "doc" and dst != rel:
                edges.append({"s": rel, "t": dst, "kind": "ref", "lt": lt})

    areas = sorted({f["area"] for f in files.values()})
    nodes = [{"id": "area::" + a, "label": a, "kind": "area", "area": a, "size": 0} for a in areas]
    nodes += [{"id": r, "label": f["title"], "kind": "doc", "area": f["area"],
               "size": f["size"], "rel": r} for r, f in files.items()]
    edges += [{"s": "area::" + f["area"], "t": r, "kind": "own"} for r, f in files.items()]

    # BFS-уровни/углы от точки входа (CLAUDE.md|README.md|первый)
    import math
    from collections import defaultdict, deque
    nid = {n["id"]: n for n in nodes}
    root_id = next((c for c in ("CLAUDE.md", "README.md") if c in nid), nodes[0]["id"])
    adj = defaultdict(set)
    for e in edges:
        adj[e["s"]].add(e["t"]); adj[e["t"]].add(e["s"])
    level, parent, dq = {root_id: 0}, {root_id: None}, deque([root_id])
    while dq:
        u = dq.popleft()
        for v in sorted(adj[u]):
            if v not in level:
                level[v] = level[u] + 1; parent[v] = u; dq.append(v)
    children = defaultdict(list)
    for v, p in parent.items():
        if p is not None:
            children[p].append(v)
    leaf = {}
    def _cnt(n):
        if not children[n]:
            leaf[n] = 1; return 1
        s = sum(_cnt(c) for c in children[n]); leaf[n] = s; return s
    _cnt(root_id)
    ang = {}
    def _asn(n, a0, a1):
        ang[n] = (a0 + a1) / 2
        ch = sorted(children[n], key=lambda c: c)
        if not ch:
            return
        tot = sum(leaf[c] for c in ch) or 1; cur = a0
        for c in ch:
            sp = (a1 - a0) * leaf[c] / tot; _asn(c, cur, cur + sp); cur += sp
    _asn(root_id, 0, 2 * math.pi)
    maxlvl = max(level.values()) if level else 0
    unreached = [n["id"] for n in nodes if n["id"] not in level]
    for i, u in enumerate(unreached):
        level[u] = maxlvl + 1; ang[u] = 2 * math.pi * i / max(1, len(unreached))
    treeset = set()
    for v, p in parent.items():
        if p is not None:
            treeset.add((p, v)); treeset.add((v, p))
    for n in nodes:
        n["lvl"] = level.get(n["id"], maxlvl + 1); n["ang"] = round(ang.get(n["id"], 0), 4)
        n["root"] = n["id"] == root_id
    for e in edges:
        e["tree"] = (e["s"], e["t"]) in treeset

    data = {"files": files, "nodes": nodes, "edges": edges, "root": root_id,
            "stats": {"files": len(files), "areas": len(areas),
                      "refs": sum(1 for e in edges if e["kind"] == "ref"),
                      "bytes": sum(f["size"] for f in files.values()),
                      "maxlvl": maxlvl, "unreached": len(unreached), "pretty": pretty}}
    payload = json.dumps(data, ensure_ascii=False).replace("</", "<\\/")
    html = _MAP_HTML.replace("__DATA__", payload).replace("__ROOTNAME__", root.name)
    out.parent.mkdir(parents=True, exist_ok=True)
    out.write_text(html, encoding="utf-8")
    return {"out": str(out), "files": len(files), "refs": data["stats"]["refs"],
            "unreached": len(unreached), "pretty": pretty}


# ─────────────────────────── serve ───────────────────────────
def cmd_serve(root: Path, port: int):
    import http.server, socketserver, functools
    docroot = root / "docs"
    if not (docroot / "docs-map.html").exists():
        docroot = root
    handler = functools.partial(http.server.SimpleHTTPRequestHandler, directory=str(docroot))
    with socketserver.TCPServer(("127.0.0.1", port), handler) as httpd:
        print(f"GitMark serve → http://127.0.0.1:{port}/docs-map.html  (Ctrl-C стоп)")
        try:
            httpd.serve_forever()
        except KeyboardInterrupt:
            print("\nстоп")


# ─────────────────────────── CLI ───────────────────────────
def _csv(v):
    return [x.strip() for x in v.split(",") if x.strip()] if v else None


def main(argv=None):
    ap = argparse.ArgumentParser(prog="gitmark", description="GitMark Memory Bank — md+git knowledge base CLI")
    ap.add_argument("--root", default=None, help="корень репо (по умолчанию — авто по .git)")
    sub = ap.add_subparsers(dest="cmd", required=True)
    sub.add_parser("index", help="построить индекс").add_argument("--force", action="store_true",
                                                                  help="(совместимость; индекс всегда пересобирается)")
    sp = sub.add_parser("search", help="искать")
    sp.add_argument("query"); sp.add_argument("-k", type=int, default=8); sp.add_argument("--json", action="store_true")
    sp.add_argument("--type", help="только эти node_type/type, через запятую")
    sp.add_argument("--status", help="только эти status, через запятую")
    sp.add_argument("--service", help="только эти service, через запятую")
    sp.add_argument("--scope", choices=["all", "live", "history"], default="all",
                    help="live — без исторических plan/report; history — только они")
    qp = sub.add_parser("query", help="структурный запрос по frontmatter",
                        description="Условия (AND): key=val  key!=val  key~sub  key>val  key<val  key?  !key. "
                                    "Альтернативы через |: status=draft|active. Вложенные ключи: verified.by, "
                                    "links.depends_on. Вычисляемые: path, area, type, trust, stale.")
    qp.add_argument("cond", nargs="*")
    qp.add_argument("--fields", default="path,type,title,status", help="колонки вывода")
    qp.add_argument("--count-by", help="посчитать по значениям ключа (списки разворачиваются)")
    qp.add_argument("--json", action="store_true")
    mp = sub.add_parser("map", help="HTML обзор+граф"); mp.add_argument("-o", "--out", default=None)
    sv = sub.add_parser("serve", help="локальный http"); sv.add_argument("-p", "--port", type=int, default=8799)
    sub.add_parser("stat", help="статистика")
    lp = sub.add_parser("lint", help="проверить онтологию (I1–I8)")
    lp.add_argument("paths", nargs="*", help="ограничить файлами (по умолчанию — все docs/)")
    lp.add_argument("--strict", action="store_true", help="exit 1 при любых ERR")
    lp.add_argument("--json", action="store_true")
    hp = sub.add_parser("health", help="скоркард БЗ"); hp.add_argument("--json", action="store_true")
    sub.add_parser("version", help="версия")
    a = ap.parse_args(argv)
    root = Path(a.root).resolve() if a.root else repo_root(Path.cwd())

    if a.cmd == "index":
        r = cmd_index(root, a.force)
        print(f"✓ index: {r['files']} файлов · {r['chunks']} чанков · {r['links']} ссылок · "
              f"trigram={'on' if r['trigram'] else 'OFF'} → {r['db']}")
    elif a.cmd == "search":
        res = cmd_search(root, a.query, a.k, _csv(a.type), _csv(a.status), _csv(a.service), a.scope)
        if a.json:
            print(json.dumps(res, ensure_ascii=False, indent=2)); return
        if not res:
            print("ничего не найдено"); return
        for r in res:
            head = f" › {r['heading']}" if r["heading"] else ""
            tags = " ".join(x for x in (r["node_type"], r["status"],
                                        "stale" if r["stale"] else "",
                                        "✓human" if r["trust"] == "human" else "") if x)
            tags = f" \033[36m{tags}\033[0m" if tags else ""
            print(f"\033[32m{r['path']}:{r['line']}\033[0m{head}{tags}  \033[90m[{r['via']}]\033[0m")
            print(f"   {r['snippet'][:200]}")
    elif a.cmd == "query":
        r = cmd_query(root, a.cond, a.count_by)
        if a.json:
            print(json.dumps(r, ensure_ascii=False, indent=1, default=str)); return
        if a.count_by:
            for v, c in r["counts"]:
                print(f"{c:>5}  {v}")
        else:
            fields = _csv(a.fields)
            for row in r["rows"]:
                print("  ".join(", ".join(str(x) for x in _get_path(row, f)) or "—" for f in fields))
        print(f"\n{r['matched']} из {r['total']} документов с frontmatter")
    elif a.cmd == "map":
        out = Path(a.out) if a.out else (root / "docs" / "docs-map.html")
        r = cmd_map(root, out)
        warn = "" if r["pretty"] else "  (raw md — `pip install markdown` для рендера)"
        print(f"✓ map: {r['out']} · {r['files']} файлов · {r['refs']} ссылок · "
              f"{r['unreached']} вне индекса{warn}")
    elif a.cmd == "serve":
        cmd_serve(root, a.port)
    elif a.cmd == "stat":
        s = cmd_stat(root)
        if not s.get("indexed"):
            print("индекс не построен — `gitmark index`"); return
        types = " ".join(f"{t}:{n}" for t, n in s["types"])
        print(f"GitMark · {s['files']} файлов · {s['areas']} папок · {s['chunks']} чанков · "
              f"{s['links']} ссылок ({s['typed_links']} типизир.) · {s['bytes']//1024} KB · "
              f"trigram={'on' if s['trigram'] else 'off'}\n  типы: {types or '—'}")
    elif a.cmd == "lint":
        r = cmd_lint(root, a.paths or None)
        if a.json:
            print(json.dumps({"errors": len(r["errors"]), "warnings": len(r["warnings"]),
                              "checked": r["checked"],
                              "issues": [dict(zip(("level", "code", "path", "msg"), i)) for i in r["issues"]]},
                             ensure_ascii=False, indent=1))
        else:
            order = {"ERR": 0, "WARN": 1}
            codes = {}
            for lvl, code, path, msg in sorted(r["issues"], key=lambda x: (order[x[0]], x[1], x[2])):
                codes[code] = codes.get(code, 0) + 1
                col = "\033[31m" if lvl == "ERR" else "\033[33m"
                print(f"{col}{lvl}\033[0m \033[90m{code}\033[0m {path} — {msg}")
            ne, nw = len(r["errors"]), len(r["warnings"])
            summary = " · ".join(f"{c}×{n}" for c, n in sorted(codes.items())) or "—"
            mark = "\033[32m✓ чисто\033[0m" if ne == 0 and nw == 0 else f"\033[31m{ne} ERR\033[0m · \033[33m{nw} WARN\033[0m"
            print(f"\n{mark}  ({r['checked']} файлов · {summary})")
        if a.strict and r["errors"]:
            sys.exit(1)
    elif a.cmd == "health":
        h = cmd_health(root)
        if a.json:
            print(json.dumps(h, ensure_ascii=False, indent=1)); return
        print(f"GitMark health · {h['score']}/100 · {h['docs']} доков (+{h['indexes']} индексов)")
        print(f"  типизировано {h['typed_pct']}% · title {h['title_pct']}% · description {h['description_pct']}%"
              f" · updated {h['updated_pct']}%")
        print(f"  типизир. связи {h['typed_links_pct']}% · связь с кодом {h['code_links_pct']}%"
              f" · сирот {h['orphans']} · битых ссылок {h['broken_links']}")
        print(f"  trust {h['trust']} · stale {h['stale']} · дублей {h['duplicate_groups']}")
        for g in h["duplicates"][:5]:
            print(f"    дубль: {' = '.join(g)}")
        print(f"  типы: {' '.join(f'{t}:{n}' for t, n in h['types']) or '—'}")
    elif a.cmd == "version":
        print(f"gitmark {VERSION}")

# GitMark — knowledge-base search

This plugin treats the repo's markdown as a **md + README(index) + git** knowledge base.
Markdown is the source of truth; the search index and HTML map are **derived** and
regenerated from md (`.gitmark/` is gitignored). The CLI is pure Python stdlib (PyYAML is
used if installed, otherwise a built-in YAML subset parser).

Script: `${CLAUDE_PLUGIN_ROOT}/skills/kb-search/gitmark.py` (when run as a project-local
copy, it's `.claude/skills/kb-search/gitmark.py`).

## Two kinds of questions → two commands

| Question | Command |
|---|---|
| **Where is X described / how does X work?** (text) | `search "<query>"` |
| **Which / how many docs have property P?** (structure) | `query key=val …` |

`search` is full-text; `query` reads frontmatter straight from the md files (no index).
Don't grep frontmatter by hand — `query` understands lists, nested keys and OKF trust fields.

## Commands

```bash
G="python3 ${CLAUDE_PLUGIN_ROOT:-.claude/plugins/gitmark}/skills/kb-search/gitmark.py"

$G index                          # (re)build .gitmark/index.db (fast, always full)
$G search "<query>" [-k 8]        # one result per file: path:line › heading [type status]
$G search "<q>" --type runbook,gotcha --status active    # filter by frontmatter
$G search "<q>" --scope live      # skip historical plan/report snapshots (or: history)
$G query type=decision status!=deprecated --fields path,title,updated
$G query type=plan --count-by service                     # group & count (lists unrolled)
$G query 'generated.by~claude' trust=unverified           # agent-written, nobody verified
$G query 'updated<2026-01-01' type=runbook                # possibly outdated runbooks
$G health                         # KB scorecard: typed %, description %, links, trust, stale
$G lint [paths…] [--json]         # ontology check (I1–I8)
$G map -o docs-map.html           # self-contained HTML: tree + rendered md + link graph
$G stat | version
```

`query` conditions (AND-ed): `key=val` · `key!=val` · `key~substr` · `key>val` /
`key<val` (ISO dates compare as strings) · `'key?'` exists · `'!key'` missing ·
alternatives `status=draft|active` · nested `verified.by`, `links.depends_on`.
Computed keys: `path`, `area`, `type` (= `node_type`), `trust` (`unverified|machine|human`),
`stale`. Quote conditions with `?`, `!`, `<`, `>`, `|` in the shell.

## Workflow

1. Docs changed since the last index → `$G index`.
2. `$G search "<terms>"`. Results are **per file**, best section first; typed KB docs
   rank above stray READMEs, `deprecated`/`archived`/stale docs are demoted (and labeled).
   `[via]` shows which channels matched: `chunk` (terms in a section), `doc`
   (title/description/tags/path), `phrase` (exact substring), `fuzzy` (typos/forms).
3. Open the returned `file:line` and read the exact place.
4. **Miss?** Reformulate once or twice before giving up: the exact identifier
   (`MAX_RETRIES`, `api-gw-02`), the other language (ru↔en), a synonym
   (деплой/выкатка, rate limit/лимит запросов). Search is lexical — it can't guess synonyms.
5. Trust signals in results: `stale` = past its `stale_after`; `✓human` = verified by a
   person. Prefer a verified, live doc over a stale one when they disagree.

## Principles

- **Markdown is the source of truth.** Edit knowledge in `.md`, never the index.
- **Don't commit `.gitmark/`** (it's in `.gitignore`).
- What gets indexed: md files git sees (tracked + untracked, minus `.gitignore`), minus
  `.gitmarkignore` prefixes (one path per line — e.g. a docs copy used as test data).
- How to *maintain* the KB (ontology, file placement, trust fields) — see `kb-curate`.

              supersedes: [arch.md]
              documents: [../../src/missing.py]
            ---
            # Architecture v2
            Gateway forwards to billing via the queue. See [old](arch.md) and [gone](nope.md).
            """)
        write(r, "notes/scratch.md", "# Scratch\nTODO: ask about billing.\n")
        write(r, "vendor-ish/lib.md", "# Vendored\nbilling gateway\n")
        write(r, ".gitignore", "vendor-ish/\n")
        subprocess.run(["git", "init", "-q", str(r)], check=True)

    def tearDown(self):
        self.tmp.cleanup()

    def test_discovery_respects_gitignore_and_gitmarkignore(self):
        write(self.root, ".gitmarkignore", "notes\n")
        rels = {p.relative_to(self.root).as_posix() for p in g.iter_md(self.root)}
        self.assertNotIn("vendor-ish/lib.md", rels)
        self.assertNotIn("notes/scratch.md", rels)
        self.assertIn("docs/reference/arch2.md", rels)

    def test_search_prefers_typed_live_doc(self):
        g.cmd_index(self.root)
        res = g.cmd_search(self.root, "billing gateway", 5)
        self.assertEqual(res[0]["path"], "docs/reference/arch2.md")
        self.assertEqual(res[0]["node_type"], "reference")
        only_dep = g.cmd_search(self.root, "billing", 5, statuses=["deprecated"])
        self.assertEqual([r["path"] for r in only_dep], ["docs/reference/arch.md"])
        self.assertEqual(g.cmd_search(self.root, "billing", 5, scope="history"), [])

    def test_lint_typed_links(self):
        codes = {(i[1], i[2]) for i in g.cmd_lint(self.root)["issues"]}
        self.assertNotIn(("I6", "docs/reference/arch2.md"), codes)     # target is deprecated
        self.assertIn(("I7", "docs/reference/arch2.md"), codes)        # src/missing.py
        self.assertIn(("I4", "docs/reference/arch2.md"), codes)        # nope.md

    def test_query(self):
        r = g.cmd_query(self.root, ["type=reference", "status!=deprecated"])
        self.assertEqual([x["path"] for x in r["rows"]], ["docs/reference/arch2.md"])
        r = g.cmd_query(self.root, ["description?"])
        self.assertEqual(r["matched"], 1)
        r = g.cmd_query(self.root, ["links.supersedes~arch"], count_by="status")
        self.assertEqual(r["counts"], [("active", 1)])
