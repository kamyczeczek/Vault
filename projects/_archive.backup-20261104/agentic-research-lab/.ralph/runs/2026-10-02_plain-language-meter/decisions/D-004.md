# D-004 — production eval-set contract and seed v1

## Question

What concrete, reproducible production evaluation set (and its seed) does the
first tier-1 comparison run use, so comprehension is scored on held-out
passages rather than on the synthetic D-003 fixture?

## Context

- D-001 RESOLVED: tier-1 = held-out lay-reader comprehension (source-derived
  question bank, answers known by construction); tier-2 = G-Eval-style rubric
  proxy; tier-3 = FactPICO-style faithfulness as a safety counter-metric.
- D-002 RESOLVED: the comparison design is written to
  `docs/research/plain-language-meter.md` (G1). The harness skeleton
  (`scripts/plain_language_meter.py`) is G2.
- D-003 RESOLVED: the deterministic *fixture* ("Alpha matters.") verifies
  wiring only and explicitly defers the production set, which "must contain at
  least 20 held-out passages, stratified by domain and length, with five
  pre-generated items per passage." That production set is this node.
- The design's eval protocol requires items generated **from the source**
  (oracle-first) and stored with expected answers **before** any candidate
  summary is scored; the question bank is never generated from a candidate.

## Resolution

RESOLVED. Freeze a two-part contract and deliver seed v1:

1. **Eval-set artifact** `knowledge/eval_sets/plain_language_v1.json` — a
   versioned, fingerprinted (sha256 of the full set) collection of held-out
   passages. Each passage records `id`, `domain`, `length_bucket`
   (short/medium/long by char count), `char_count`, `split` (dev/test), and
   `items` — each item `{prompt, answer, kind}`.
2. **Builder** `scripts/build_plain_language_eval_set.py` — deterministic,
   oracle-first, stdlib-only. It reads passage files, strips front-matter,
   extracts the longest prose sentences (oracle: the source itself, not any
   candidate), and emits the artifact. Fail-closed: an empty passage or a
   passage yielding fewer than `--min-items` usable sentences raises
   `ValueError` rather than emitting a thin passage.

**Seed v1** is **3 real, KB-scale dense agent outputs** in this workspace
(`docs/research/trustworthy-agent-tests.md`,
`docs/research/plain-language-meter.md`,
`docs/research/forge-guardrails-ab.md`). The seed verifies the
contract and plumbing (fingerprint, stratification, oracle-first item
storage, dev/test split, fail-closed), not production quality. The
reflection-digest candidate (`reflection/digests/decision_graphs_workflow.md`)
was probed out: its prose is bullet/code-dense, so the builder's `--min-items 5`
gate correctly rejects it (1 usable sentence). G4 surfaced this — a signal,
not a defect: the fail-closed gate is doing its job.

**Honest limitation, recorded now:** the deterministic source-derived
generator emits **recall** items (top-N prose sentences, "What does the source
state: <s>?"). The design's 3-multiple-choice + 2-recall-per-passage target and
MC distractor generation are **model-backed** (an adapter seam), as is the
20-passage production set; those are deferred to a budgeted step. Seed v1 is
therefore a wiring proof, and its verdict cannot substitute for G3's human
groundedness check or for a model-backed production run.

**dev/test split (seed):** deterministic by `char_count` (longest half →
`test`, shortest half → `dev`; tie-break by `id`). The 20-passage production
set performs the real stratified split.

## Contract

- The source is the only input to seed item generation; no candidate text
  enters. Every item stores its expected answer before scoring.
- `knowledge/eval_sets/plain_language_v1.json` is generated by the builder
  and committed; the builder is the single source of truth (regenerate, do
  not hand-edit).
- The builder is `--min-items` gated (default 5) and fail-closed.
- Lay-reader cast and model identifiers stay runtime configuration, not
  embedded in the seed (per D-003).
- `G4` is the new observable gate: the builder runs clean on the seed and
  emits a fingerprinted, stratified, oracle-first set.

## Evidence

See I-004: builder self-run on the 3 seed passages, focused test suite green,
`git diff` on the generated JSON, and the root workspace-integrity gate.

## Acceptance interpretation

G4 proves the plumbing. It does **not** advance the mechanism comparison —
that is D-005 (score the three prompt-layer mechanisms on the set), which
needs model access and is a human/budget call. G3 (human end-to-end
groundedness) stays human-owned and is unaffected by this node.
