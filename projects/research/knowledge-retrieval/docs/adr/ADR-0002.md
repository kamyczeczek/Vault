# ADR-0002: Lokalna konwencja haszowa dla pochodnych (D5/ADR-0003)

## Status

Accepted

## Context

W ARL (D5/ADR-0003) wszystkie pochodne (chunki, bazy, wyniki benchmarków) są
adresowane haszem treści (SHA256), a nie ścieżką pliku. To sprawia, że:

- zmiana nazwy pliku nie psuje odwołań
- można weryfikować, czy pochodna jest aktualna bez porównywania zawartości
- garbage collection jest deterministyczny (hash = key)

## Decision

W knowledge-retrieval używamy tej samej konwencji:

- `library/hash_content.py` — funkcja `hash_content(path) -> str` (SHA256, stdlib only)
- Pochodne w `reports/` i `scripts/_scratch/` są nazwane `{hash}_{opis}.json`
- Jeśli hash się nie zgadza, plik jest przestarzały i może być usunięty

## Consequences

- Wszystkie nowe raporty i wyniki benchmarków będą miały hash w nazwie
- Można dodać gate `check_derived_freshness.py` w przyszłości (opcjonalne)
- Wymaga `library/hash_content.py` w repo (nie w `.gitignore`)
