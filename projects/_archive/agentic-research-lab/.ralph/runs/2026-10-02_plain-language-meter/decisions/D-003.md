# D-003 — freeze the evaluation fixture contract

## Question
What concrete fixture and scoring contract should the first meter run use so the harness is reproducible without claiming human validity?

## Resolution
Use a small deterministic fixture for harness verification only: one source containing two explicit factual sentences, with one source-derived recall item per sentence. The production evaluation set remains separate and must contain at least 20 held-out passages, stratified by domain and length, with five pre-generated items per passage. The lay-reader cast and model identifiers are runtime configuration, not embedded in the skeleton.

## Contract
- Source text is the only input to oracle-backed item generation.
- Every generated item stores its expected answer before candidate scoring.
- Empty sources and mismatched response counts fail closed with `ValueError`.
- The CLI emits JSON containing `items`, `comprehension`, and the four-key rubric dictionary.
- Synthetic fixtures verify wiring only; G3 requires a human spot check and cannot be satisfied by this fixture.

## Evidence
The public CLI was exercised on `Alpha matters.` and returned JSON with one item and `comprehension: 1.0`. The focused and parity tests pass 30/30, and the full project quality gate passes 21/21.

## Acceptance interpretation
G3 is not a sentence-level proxy agreement test. The human acceptance path is one realistic end-to-end research task: research a question, ingest the source into the project corpus, retrieve it through the knowledge graph, reflect on the evidence, and implement the resulting knowledge. The reviewer checks groundedness and an inspectable artifact trail at every stage.
