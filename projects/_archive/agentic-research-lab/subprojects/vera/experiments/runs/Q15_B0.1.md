## 1. Question
Does the 2-Action Rule reduce context-rot incidents — and how would you design the ablation to prove it rather than assume it?

## 2–4. Sources
`00_plan_persistence_context_window_compaction` (context rot: Chroma 2025, 18 frontier models, degradation at every context increment; Liu et al. 20+ point drops when relevant material sits mid-context), `50_graph_engineering...` (Anthropic's definition of context rot: ability to recall a given fact degrades), `01_build_faster_by_coding_slower` (tickets to guard against session loss / context degradation), workspace: CONTEXT.md 2-Action Rule.

## 5–6. Claims (jsonl)
c01: Context rot is real and monotonic: performance degrades with context growth even on trivial tasks (Chroma 2025, 18 models).
c02: The 2-Action Rule (persist after every 2 tool ops) targets rot by moving facts out of the window into files, making them re-fetchable instead of decay-in-window.
c03: The ablation below does NOT yet prove the rule works — it is a design; no in-corpus incident data exists for this lab.

## 7. Limiting evidence
The rule's interval (2 ops) is unexplained by any retrieved source; it is a heuristic. Rot data is about window size, not about re-fetch behavior; whether re-fetching restored facts actually prevents decay is a separate claim (the reorientation-cost chunk `00_reflection_reorientation_cost` argues bounded state + query beats growing files — consistent but not a proof of the 2-op interval).

## 8. Mechanisms
Persistence → facts externalized → next turn re-fetches on demand (query-over-read) → effective context window stays bounded. Rot is broken if re-fetch latency < decay loss.

## 9. Failure modes
- Persisting junk (file bloat, unfindable notes) → re-fetch cost exceeds decay saved
- Persisting too late (>2 ops, loss already happened mid-reasoning)
- Re-reading whole files instead of targeted queries (violates reorientation-cost rule)

## 10. Confidence
High on rot existence; low-to-medium on the rule's causal effect (no direct evidence — that is the point of the experiment).

## 11. Designed ablation (answer)
- **Units:** N long research sessions (≥20 tool ops) on identical task families.
- **Arms:** A) 2-Action Rule enforced (persist every 2 ops); B) end-of-session persist only (current default); C) control with no persistence.
- **Dependent variable:** "recovery rate" — on a surprise checkpoint prompt at op 20 and op 40, fraction of key facts (pre-listed, blinded set of 20) that the agent correctly reproduces without re-reading its own notes.
- **Instrument:** checkpoint prompts are scripted; facts are scored against the blinded set; all arms get identical retrieval access.
- **Negative control:** a no-op persistence variant (append empty note) — must score like arm C; otherwise the effect is from file-existence, not content.
- **Attribution:** root-cause split of failures (forgot vs. forgot-and-couldn't-retrieve vs. re-fetched-wrong-file) so a win can't be claimed for the wrong mechanism.
- **Stop rule:** if A ≈ B at op 40, the 2-op interval adds nothing; abandon interval, keep end-persist.
